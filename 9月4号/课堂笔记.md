# 9月4号 课堂笔记

### 为什么需要数据驱动

- 一条用例要测试不同数据（如登录的正确 / 错误用户名、正确 / 错误密码），需要写很多个 YAML 文件，麻烦
- 只是变数据，不想写那么多 YAML 文件

### 数据驱动思路

- 数据不写死，用变量方式传数据（`{{uname}}`、`{{pwd}}`、`{{expected}}`）
- 数据驱动把数据传到用例中去

### 用例结构（用例模板 + 数据驱动）

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录用例标题
  一级模块: 登录模块
  二级模块: 登录功能

前置脚本: ""
后置脚本: ""

用例步骤:
  - 发送登陆接口:
      操作类型: 发送请求POST
      请求地址: '{{URL}}'
      URL参数:
        s: /api/user/login
        application: app
        application_client_type: weixin
      请求数据:
        accounts: "{{uname}}"
        pwd: "{{pwd}}"
        type: "username"

  - 提取响应数据msg:
      操作类型: 提取数据JSON
      表达式: $..msg
      下标: 0
      变量名: my_msg

  - 断言:
      操作类型: 断言文本相等
      期望结果: "{{expected}}"
      实际结果: my_msg

数据驱动:
  - 描述标题: 正确用户名和密码
    uname: youyi
    pwd: 123456
    expected: 登录成功

  - 描述标题: 错误用户名和正确密码
    uname: yyouyi
    pwd: 123456
    expected: "登陆账号不存在"

  - 描述标题: 正常用户名和错误密码
    uname: youyi
    pwd: 1234567
    expected: "登陆账号不存在"
```

### 代码思路

1. 把用例结构（模板）拿出来
2. 把数据驱动的数据拿出来
3. 组合：有几组数据就组合成几条用例
4. 组合每条用例的标题：`用例标题 + 描述标题`

- 数据驱动的数据放在全局变量中，用例里通过渲染 `{{}}` 拿到
- 执行时：正确用户名和密码 + 模板 = 第 1 条用例；错误用户名 + 模板 = 第 2 条；错误密码 + 模板 = 第 3 条
