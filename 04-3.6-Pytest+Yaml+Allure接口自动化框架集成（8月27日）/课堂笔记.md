## 1. 新手先认识 6 个词

### 1.1 YAML

一种专门用来写配置和用例的文本格式。特点是不用写括号、不用写引号（大部分时候），靠**缩进**表示层级，人看起来很清楚。

### 1.2 pytest

Python 里最常用的测试框架。它的作用是：

```text
找到测试用例
一条条执行
汇总结果（几条通过、几条失败）
```

### 1.3 参数化（parametrize）

一条测试函数，喂给它多组数据，就变成多条用例。这是接口自动化的核心机制。

### 1.4 Allure

生成测试报告的框架，能把用例标题、模块、步骤渲染成一份网页报告。本节文件夹标题里有它，但真正的配置在下一课展开。

### 1.5 依赖清单

一个文件，记录项目用到了哪些第三方库、什么版本。别人拿到你的项目，照着装一遍就能跑。

### 1.6 相对路径

```text
./    当前目录
../   上一级目录
../../ 上上级目录
```

## 2. 整体执行流程

```text
1. 把项目依赖导出成 requirements.txt
2. 用 YAML 写一条用例（1_login.yaml）
3. Python 读取 YAML，变成字典
4. 把字典交给 pytest 参数化，生成测试用例
5. 执行器按“操作类型”找到对应的方法，发请求
6. 打印结果
```

对应到本节的四个文件：

```text
examples/api-cases-yaml/1_login.yaml   -> 用例（测什么）
HAT/parse/YamlCaseParser.py            -> 读取 YAML
HAT/keywords/api_client.py             -> 请求方法（怎么发）
HAT/core/testrun.py                    -> 执行器（pytest 入口）
```

## 3. 第一步：导出和安装项目依赖

### 3.1 导出

```powershell
pip freeze > requirements.txt
```

`pip freeze` 会把当前环境里装的所有库和版本打印出来，`>` 表示“把输出写进文件”。

导出的内容大概长这样：

```text
Jinja2==3.1.6
pytest==9.1.1
PyYAML==6.0.3
requests==2.34.2
```

### 3.2 安装

别人拿到你的项目，或者你换了电脑，只要：

```powershell
pip install -r requirements.txt
```

`-r` 的意思是“按这个文件里列出的清单装”。

### 3.3 下载慢就换镜像

```powershell
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

`-i` 是指定下载源，后面这个是清华镜像。

### 3.4 三个注意事项

```text
文件名是 requirements.txt，中间有 s，别写成 requirement.txt
命令要在项目根目录下执行，不然找不到文件
这个文件要跟着项目一起提交，别人才能还原环境
```

> 顺带一提：仓库里好几节课的文件夹都同时有 `requirement.txt` 和 `requirment.txt`（一个少写了一个 e），这是拼写不一致留下的，装依赖时以 `requirements.txt` 为准。

## 4. YAML 语法

### 4.1 四条基本规则

```text
用 键: 值 表示字典，冒号后面必须有空格
用 - 表示列表
同一层级要左对齐，缩进只能用空格，不能用 Tab
用 # 写注释
```

**冒号后面的空格**最容易忘。`name:张三` 是错的，`name: 张三` 才对。

### 4.2 一个最简单的例子

```yaml
# stu.yaml
name: zhangsan
age: 18
list:
  - 1
  - 2
  - 3
```

### 4.3 YAML 的类型会变成 Python 的什么

这是新手最容易吃亏的地方。我拿本节的 `test.yaml` 跑了一遍，实测结果：

| YAML 写法 | Python 里的值 | 类型 |
|---|---|---|
| `age: 18` | `18` | int |
| `name: 张三` | `'张三'` | str |
| `height: 175.5` | `175.5` | float |
| `is_student: true` | `True` | bool |
| `nickname: null` | `None` | NoneType |
| `birthday: 2008-01-01` | `datetime.date(2008, 1, 1)` | date |

**最后一行要注意**：日期格式会被自动解析成日期对象，不是字符串。如果接口就是想要字符串 `2008-01-01`，就得加引号写成 `'2008-01-01'`。

### 4.4 引号加不加，差别很大

我实测了几种最容易踩的写法：

| YAML 写法 | 读出来是什么 | 类型 |
|---|---|---|
| `pwd: 123456` | `123456` | int |
| `pwd: "123456"` | `'123456'` | str |
| `pwd: 0123456` | `42798` | int |
| `flag: yes` | `True` | bool |
| `flag: on` | `True` | bool |
| `flag: null` | `None` | NoneType |
| `v: 1.0` | `1.0` | float |
| `s: /api/user/login` | `'/api/user/login'` | str |

三个重点：

1. **不加引号的数字会变成整数**。接口要的是字符串 `"123456"`，你写成 `123456`，发过去可能就是数字，服务端可能校验失败。
2. **`pwd: 0123456` 会变成 `42798`**！因为前导 0 被当成八进制解析了。
3. **`yes`、`on`、`no`、`off` 都会变成布尔值**。如果某个参数的值恰好是这些词，一定要加引号。

所以课上的 `1_login.yaml` 里写的是：

```yaml
     请求数据:
        accounts: youyi
        pwd: "123456"
        type: username
```

`pwd` 特意加了引号，就是为了保证它是字符串。

### 4.5 列表和字典

```yaml
# 列表
hobbies:
  - 篮球
  - 音乐
  - coding

# 行内列表
tags: [student, class-3]

# 字典
contact:
  phone: "13800000000"
  email: test@example.com

# 行内字典
simple_user: { id: 1001, level: vip }
```

字典里面可以放列表，列表里面也可以放字典：

```yaml
student:
  name: 张三
  score:
    chinese: 92
    math: 98
  subjects:
    - name: 数学
      teacher: 王老师
      classroom: 301
    - name: 英语
      teacher: 李老师
      classroom: 302
```

读出来是：

```text
score        : {'chinese': 92, 'math': 98, 'english': 95}
第一个科目   : {'name': '数学', 'teacher': '王老师', 'classroom': 301}
```

### 4.6 多行文本：`|` 和 `>`

```yaml
description: |
  这是 literal block 格式。
  每一行换行都会保留。

summary: >
  这是 folded block 格式，
  多行内容会被折叠成一行。
```

实测区别：

```text
|  ->  '这是 literal block 格式。\n每一行换行都会保留。\n'      换行保留
>  ->  '这是 folded block 格式， 多行内容会被折叠成一行。\n'   换行变空格
```

### 4.7 锚点引用（`&` 和 `*`）

同一段配置要重复写好几遍时，可以用锚点：

```yaml
default_env: &default_env
  timeout: 10
  retry: 3
  content_type: application/json

dev_env:
  <<: *default_env
  base_url: http://dev.example.com

test_env:
  <<: *default_env
  base_url: http://test.example.com
  retry: 5
```

实测读出来：

```text
dev_env : {'timeout': 10, 'retry': 3, 'content_type': 'application/json', 'base_url': 'http://dev.example.com'}
test_env: {'timeout': 10, 'retry': 5, 'content_type': 'application/json', 'base_url': 'http://test.example.com'}
```

`&default_env` 是“给这段起个名字”，`*default_env` 是“把那段拿过来”，`<<:` 表示合并。注意 `test_env` 里自己写了 `retry: 5`，把继承来的 `3` 覆盖掉了。

## 5. 读取文件时的路径转义

### 5.1 问题

Windows 的路径用反斜杠 `\`，而 Python 里 `\` 是转义符：

```python
path = 'F:\test\name.yaml'
```

`\t` 会变成制表符、`\n` 会变成换行，路径就废了。

### 5.2 解决办法一：前面加 r

```python
path = r'F:\test\name.yaml'
```

`r` 表示**原始字符串**，里面的 `\` 就是普通的反斜杠，不做转义。

### 5.3 解决办法二：把 `\` 换成 `/`

```python
path = 'F:/test/name.yaml'
```

Python 在 Windows 上也能识别正斜杠，这样写最省心。

### 5.4 相对路径

```text
./       当前目录
../      上一级目录
../../   上上级目录
```

`HAT/parse/YamlCaseParser.py` 文件末尾的注释就是讲的这个：

```text
./   代表当前目录 parse
../  代表上一级目录 HAT
../../ 上上级目录 day04
```

### 5.5 最容易搞错的一点

课上特别强调：

> 相对路径要看**运行程序时所在的目录**，不是只看代码文件放在哪里。

举例：`testrun.py` 里写的是

```python
load_yaml_files('./examples/api-cases-yaml/')
```

这个 `./` 指的是**你敲命令时所在的目录**。所以必须先进到课程目录再运行：

```powershell
cd "F:\learn-code\daily-notes\04-3.6-Pytest+Yaml+Allure接口自动化框架集成（8月27日）"
python -m pytest HAT/core/testrun.py
```

如果在仓库根目录运行，就会报找不到文件。

## 6. 一条用例用字典，一组用例用列表

### 6.1 为什么要有这个约定

```text
字典 = 一条用例
列表 = 一组用例
```

因为 `pytest.mark.parametrize` 需要**遍历**一个列表：列表里有几条数据，就生成几条用例。

### 6.2 看个例子

```python
data = [
    {"case_title": "登录成功", "accounts": "youyi", "pwd": "123456"},
    {"case_title": "密码错误", "accounts": "youyi", "pwd": "000000"}
]

@pytest.mark.parametrize("caseinfo", data)
def test_case(caseinfo):
    print(caseinfo)
```

`caseinfo` 每次接住列表里的一个字典，也就是一条用例。上面这段会生成 2 条测试用例。

### 6.3 只有一条用例时为什么也要包一层列表

课上讲了这一点，很关键：

> 读出来的字典包一层列表后，即使当前只有 1 条用例，框架也能按统一方式执行。

所以 `readYaml` 函数最后写的是：

```python
case_info = []
...
case_info.append(data)
return case_info
```

它返回的是 `[一条用例]`，而不是直接返回那一条用例。这样用例变成 2 条、10 条时，执行器的代码一行都不用改。

## 7. 第一版 HAT 框架：三个文件分工

目录结构：

```text
HAT/
 ├─ core/          执行器（pytest 入口）
 │   └─ testrun.py
 ├─ parse/         解析（读 YAML）
 │   └─ YamlCaseParser.py
 └─ keywords/      关键字（发请求的方法）
     └─ api_client.py

examples/
 └─ api-cases-yaml/
     ├─ 1_login.yaml   用例
     └─ test.yaml      YAML 语法学习文件（不是用例）
```

分工一句话：

```text
parse  ：把 YAML 变成 Python 字典
keywords：字典里的“操作类型”对应哪个方法
core   ：把上面两个串起来，交给 pytest 跑
```

### 7.1 用例长什么样

`examples/api-cases-yaml/1_login.yaml`：

```yaml
# 教学用标准登录接口用例
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录接口
  一级模块: 登录模块
  二级模块: 用户登录
  优先级: P0

用例步骤:
  - 发送登录请求:
      操作类型: 发送请求POST
      请求地址: http://shop-xo.hctestedu.com
      URL参数:
        s: /api/user/login
        application: app
        application_client_type: weixin
      请求头:
        Content-Type: application/x-www-form-urlencoded
      请求数据:
        accounts: youyi
        pwd: "123456"
        type: username
```

结构就是第 07、08 课一直用到的那套：

```text
基础配置  -> 用例标题、模块（给报告用）
用例步骤  -> 列表，每一步做一件事
操作类型  -> 决定调用哪个方法
```

注意文件末尾注释掉的断言部分：

```yaml
#断言:
#  状态码: 200
#  响应消息: 登录成功
#  提取数据:
#    token: $..token
```

断言本课还没做，第 09 课才会正式加进来。

### 7.2 执行器：testrun.py

```python
import pytest
import requests

from HAT.keywords.api_client import Keywords
from HAT.parse.YamlCaseParser import load_yaml_files


client = Keywords(requests.session())


class TestRun:
    # 只执行包含用例步骤的 YAML，跳过 test.yaml 这类语法学习文件
    data = [
        case
        for case in load_yaml_files('./examples/api-cases-yaml/')
        if case.get('用例步骤')
    ]

    @pytest.mark.parametrize('data_yaml', data)
    def test_case_yaml(self, data_yaml):
        steps = data_yaml.get('用例步骤', [])
        assert steps, '用例缺少用例步骤'

        for step in steps:
            step_name, step_value = next(iter(step.items()))
            key = step_value.get('操作类型')
            try:
                key_func = client.__getattribute__(key)
            except AttributeError:
                raise AssertionError(f'{step_name} 在 Keywords 中没有找到方法：{key}')

            response = key_func(**step_value)
            print(step_name, response.status_code, response.json())
```

逐段看：

```python
client = Keywords(requests.session())
```

创建请求对象。这里传的是 `requests.session()`，所以会保持会话（第 02、03 课讲的鸭子类型，这里正好用上）。

```python
data = [
    case
    for case in load_yaml_files('./examples/api-cases-yaml/')
    if case.get('用例步骤')
]
```

读取文件夹里所有用例，然后**过滤掉没有“用例步骤”的文件**。

为什么要过滤？因为 `test.yaml` 是讲 YAML 语法的练习文件，它只是一堆示例数据，不是用例。它没有 `用例步骤` 这个键，所以会被这一行筛掉。

```python
for step in steps:
    step_name, step_value = next(iter(step.items()))
```

每个步骤长这样：

```python
{'发送登录请求': {'操作类型': '发送请求POST', '请求地址': ..., ...}}
```

`next(iter(step.items()))` 取出第一组键值对，于是：

```text
step_name  = '发送登录请求'
step_value = {'操作类型': '发送请求POST', '请求地址': ...}
```

```python
key = step_value.get('操作类型')
key_func = client.__getattribute__(key)
```

`操作类型` 是 `发送请求POST`，于是去 `Keywords` 里找同名的方法。找不到就抛一个看得懂的报错：

```python
raise AssertionError(f'{step_name} 在 Keywords 中没有找到方法：{key}')
```

```python
response = key_func(**step_value)
print(step_name, response.status_code, response.json())
```

字典解包后调用方法（第 03 课讲过 `**`），然后打印步骤名、状态码、返回内容。

### 7.3 请求方法：api_client.py

```python
class Keywords:
    """requests 二次封装，方法名和 YAML 中的操作类型保持一致"""

    def __init__(self, session):
        self.session = session

    def 发送请求POST(self, **kwargs):
        url = kwargs.get("请求地址", None)
        data = kwargs.get("请求数据", None)
        params = kwargs.get("URL参数", None)
        headers = kwargs.get("请求头", None)
        files = kwargs.get("文件列表", [])
        data_type = kwargs.get("请求类型", "data").lower()
        ...
```

**注意参数名全是中文**，而且和 YAML 里的键一一对应：

| YAML 里的键 | 方法里怎么取 |
|---|---|
| `请求地址` | `kwargs.get("请求地址")` |
| `请求数据` | `kwargs.get("请求数据")` |
| `URL参数` | `kwargs.get("URL参数")` |
| `请求头` | `kwargs.get("请求头")` |
| `请求类型` | `kwargs.get("请求类型", "data")` |

**方法名也要和 YAML 里的“操作类型”完全一致**：

```text
YAML 里写 操作类型: 发送请求POST
类里就要有 def 发送请求POST(...)
```

少一个字、大小写不对，就会报“没有找到方法”。

### 7.4 读取 YAML：YamlCaseParser.py

```python
def readYaml(file_path):
    case_info = []
    with open(file_path, 'r', encoding='utf-8') as f:
        data = yaml.load(f, Loader=yaml.FullLoader)
        case_info.append(data)
    return case_info
```

读**单个** YAML 文件，返回一个列表（里面是一条用例）。

```python
def load_yaml_files(file_path):
    yaml_caseInfos = []
    suite_folder = os.path.join(file_path)

    file_names = [(int(f.split("_")[0]), f) for f in os.listdir(suite_folder)
                  if f.endswith(".yaml") and f.split("_")[0].isdigit()]
    file_names.sort()
    file_names = [f[-1] for f in file_names]

    for file_name in file_names:
        file_path = os.path.join(suite_folder, file_name)
        with open(file_path, 'r', encoding='utf-8') as file:
            caseinfo = yaml.full_load(file)
            yaml_caseInfos.append(caseinfo)
    return yaml_caseInfos
```

读**整个文件夹**里符合命名规则的 YAML（第 08 课会详细讲这个函数）。

两个小细节：

```text
encoding='utf-8'  -> 不加中文会乱码
Loader=yaml.FullLoader -> 安全加载，不加会有警告
```

## 9. 常见报错和排查方法

### 9.1 `FileNotFoundError: ... 1_login.yaml`

运行目录不对。相对路径看的是**敲命令时所在的目录**，所以要先 `cd` 到课程目录：

```powershell
cd "F:\learn-code\daily-notes\04-3.6-Pytest+Yaml+Allure接口自动化框架集成（8月27日）"
```

### 9.2 YAML 解析报错（`yaml.scanner.ScannerError`）

九成是缩进问题。排查：

```text
冒号后面有没有空格？
有没有混用 Tab？（只能空格）
同一层级有没有对齐？
```

### 9.3 读出来是数字，但接口要字符串

回顾第 4.4 节。给值加上引号：

```yaml

```

### 9.4 `AssertionError: xxx 在 Keywords 中没有找到方法`

`操作类型` 和方法名不一致。检查：

```yaml
操作类型: 发送请求POST
```

```python
def 发送请求POST(self, **kwargs):   # 必须一模一样
```

### 9.5 收集到 0 条用例

说明所有 YAML 都被过滤掉了。检查文件里有没有 `用例步骤` 这个键，以及它下面是不是真的写了步骤。


## 10. 本节重点记忆

| 名称 | 作用 |
|---|---|
| `pip freeze > requirements.txt` | 导出项目依赖 |
| `pip install -r requirements.txt` | 按清单安装依赖 |
| `-i https://pypi.tuna.tsinghua.edu.cn/simple/` | 换清华镜像 |
| YAML 缩进 | 只能用空格，冒号后要空格 |
| `r'路径'` | 原始字符串，防止 `\` 被转义 |
| `/` 代替 `\` | Windows 路径的另一种写法 |
| `./` `../` | 当前目录 / 上一级目录 |
| 相对路径的基准 | 运行程序时所在的目录 |
| 字典 = 一条用例 | 列表 = 一组用例 |
| `pytest.mark.parametrize` | 有几条数据就生成几条用例 |
| `yaml.load(f, Loader=yaml.FullLoader)` | 安全读取 YAML |
| `next(iter(step.items()))` | 取字典里的第一组键值对 |
| `client.__getattribute__(key)` | 按“操作类型”找同名方法 |
| `key_func(**step_value)` | 字典解包后调用方法 |
| HAT 目录 | core 执行器 / parse 解析 / keywords 关键字 |

两句话总结：

> 框架分工：YAML 写用例，Python 读并执行。
>
> 两条纪律：YAML 里冒号后要有空格、参数名和“操作类型”必须和方法名完全一致。
