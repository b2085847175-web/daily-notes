# 9月1号 课堂笔记

### 为什么要断言

- YAML 用例运行后，无论结果如何，pytest 都显示用例成功
- 需要自己对比结果是不是想要的（肉眼判断 + 人为判断）
- 自动化：让代码帮我们判断「实际结果」和「预期结果」是否一致

### 断言的写法

- 断言 = 代码帮我们判断实际结果和预期结果是否一致
- 语法：`assert 预期结果 == 实际结果, "错误时显示的信息"`
- 比较符：`==` 相等、`>` 大于、`<` 小于、`!=` 不等于、`>=` 大于等于、`<=` 小于等于
- 错误信息可以写，也可以不写
  - 写了：用例失败时提示自定义错误信息
  - 没写：用例失败时报默认报错信息
- 断言成功：用例通过，没有任何提示

### 为什么封装断言

- 断言经常要用，所以封装起来
- YAML 用例里需要两个值：预期结果、实际结果
  - 预期结果：从需求文档 / 接口文档拿到
  - 实际结果：运行完后从接口返回结果中提取

### 封装后的断言关键字

- 优化点：一眼就能看出断言的是「大于 / 等于 / 不等于」还是「数字」
- 在 `api_keywords.py` 里封装了：
  - `断言文本`（底层，支持比较符 + 断言类型）
  - `断言文本相等`、`断言文本不相等`、`断言文本包含`
  - `断言数字相等`、`断言数字大于`、`断言数字大于等于`、`断言数字小于`、`断言数字小于等于`、`断言数字不等于`
