# 9月6号 课堂笔记

### 为什么需要 Session 复用

- `requests` 每次请求都是独立的，相当于每次新开一个浏览器
- 第一次请求的结果（cookie 等）不会自动传给第二个接口，系统会认为你是新用户，提示未登录
- 需要保留之前的会话内容

### 两种鉴权方案

1. cookie/session 鉴权：会话要保持在同一个 session 会话中
2. token 鉴权：不需要 session，只需要把 token 传给下一个接口

- 商城项目：接口文档传递 token 值 → 属于 token 鉴权
- 框架要通用，两种方式都处理

### Session 复用开关

- 在 `context.yaml` 配置 `session_reuse` 变量（经常变化）

- `session_reuse = True`：只创建一次 `requests.session()`，保存这个对象，后续都用它（保持同一个会话）
- `session_reuse = False`：每次都创建新的 `requests.session()`，不记录之前的会话

### 疑问解答

- token 鉴权为什么还写 `requests.session()`？
  - 框架是通用的，两种方式都处理
  - 发请求用 `requests.session()` 没关系，没有 cookie 就不带 cookie
  - 对商城项目（token 鉴权）没用，但如果别的项目是 cookie/session 鉴权就有用
