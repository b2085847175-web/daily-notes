# 第07课 课堂笔记｜用例前后置条件设计（8月30日）

> 本节目标：给 YAML 用例加上“前置脚本”和“后置脚本”。用例执行前先跑一段代码准备数据（比如把测试账号写进全局变量），用例执行后再跑一段代码清理数据。以后“跑用例的时候才产生、跑完又不要了”的数据，都有地方放了。

---

## 0. 先用一句话理解本节

上一节我们把“固定不变的环境数据”（URL、账号、密码）统一放进了 `context.yaml`。

但还有一类数据是**跑用例的过程中才产生的**，`context.yaml` 放不了：

- 注册接口每次要一个不重复的手机号
- 登录成功后拿到的 `token`
- 下单前要先清空购物车
- 用例跑完要把刚才注册的账号删掉

这些“执行前要准备、执行后要清理”的动作，就是本节要讲的**前置脚本**和**后置脚本**。

一句话：

```text
用例执行前 -> 跑前置脚本 -> 把数据写进 context（全局变量）
          -> 用例步骤里用 {{变量名}} 取值
          -> 发请求
用例执行后 -> 跑后置脚本 -> 清理数据
```

也就是：

```text
前置脚本   -> 准备数据（setup）
后置脚本   -> 清理数据（teardown）
context    -> 前后置脚本共用的全局变量字典
{{变量名}} -> 用例步骤里取前置脚本准备好的数据
```

---

## 1. 新手先认识 5 个词

### 1.1 前置脚本（setup）

**用例执行之前**要跑的代码。

比如登录前先准备一个账号：

```text
前置脚本：把账号 youer 放进全局变量
```

### 1.2 后置脚本（teardown）

**用例执行之后**要跑的代码。

比如用例跑完把刚才产生的测试数据删掉：

```text
后置脚本：清理测试数据
```

### 1.3 context

`context` 是框架传给脚本的**全局变量字典**。

脚本里写：

```python
context.update({'name': 'youer'})
```

就等于往全局变量里加了一条：

```text
name = youer
```

后面用例步骤里就能用 `{{name}}` 取到它。

**关键理解**：脚本里的 `context` 不是随便一个新字典，它指向的就是 `g_context().show_dict()` 那个字典本身。所以脚本里改了它，全局变量就真的变了。

### 1.4 exec：把字符串当代码执行

`exec` 是 Python 的内置函数，作用是“把一段字符串当成代码跑一遍”：

```python
exec("print('你好')")
```

输出：

```text
你好
```

本节专门用它来执行 YAML 里写的那句脚本。

### 1.5 eval：把字符串当表达式求值

`eval` 也是内置函数，作用是“把一段字符串当成一个表达式算一算，把结果返回”。

两者区别：

| 函数 | 作用 | 有没有返回值 |
|---|---|---|
| `exec` | 执行一段代码 | 没有（返回 `None`） |
| `eval` | 计算一个表达式 | 有，返回结果 |

例子：

```python
exec("x = 1 + 1")     # 执行完 x 变成 2，但没有返回值
y = eval("1 + 1")     # y 就是 2
```

本节两个都会用到：

```text
eval  -> 把渲染后的字符串还原成列表 / 字典
exec  -> 真正去执行那一条脚本
```

## 2. 整体执行流程

先看全局，不急着看代码细节：

```text
1. 读取 context.yaml，把 URL 放进全局变量
2. 读取 login.yaml，拿到用例数据
3. 复制一份全局变量，得到本次用例渲染用的 context
4. 取出「前置脚本」，先渲染，再 eval 还原成列表
5. 一条一条执行前置脚本，脚本里往全局变量写数据
6. 进入用例步骤循环
7. 每一步都重新复制一份全局变量（此时已包含前置脚本写的数据）
8. 渲染步骤里的 {{URL}}、{{name}}
9. 根据「操作类型」找到对应的关键字方法
10. 发送接口请求
11. 步骤跑完，取出「后置脚本」，同样渲染 + 执行
```

对应到文件和函数：

```text
context.yaml
  -> YamlCaseParser.load_context_from_yaml()
  -> g_context().set_by_dict()

login.yaml 里的 前置脚本
  -> VarRender.refresh()
  -> eval()
  -> run_script.exec_script()
  -> exec(script, {'context': ...})
  -> context.update(...) 写进全局变量

login.yaml 里的 用例步骤
  -> VarRender.refresh()
  -> eval()
  -> Keywords.发送请求POST()
  -> requests 发送请求

login.yaml 里的 后置脚本
  -> 和前置脚本同一套流程
```

**记住一个顺序**：

```text
全局变量 -> 前置脚本 -> 渲染步骤 -> 接口请求 -> 后置脚本
```

## 3. YAML 里怎么写：login.yaml

文件位置：

```text
examples/api-cases-yaml/login.yaml
```

本节完整内容：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录用例标题
  一级模块: 登录模块
  二级模块: 登录功能

前置脚本:
  - "context.update({'name': 'youer'})"
后置脚本: ""

用例步骤:
  - 发送登陆接口:
      操作类型: 发送请求POST
      请求地址: '{{URL}}'
      URL参数:
        s: /api/user/login
        application: app
        application_client_type: weixin
      请求数据:
        accounts: '{{name}}'
        pwd: '123456'
        type: username
```

### 3.1 和上一节比，多了什么

只多了两块：

```yaml
前置脚本:
  - "context.update({'name': 'youer'})"
后置脚本: ""
```

外加请求数据里这一行从写死变成了变量：

```yaml
accounts: '{{name}}'
```

上一节这里是：

```yaml
accounts: youyi
```

### 3.2 前置脚本、后置脚本的三种写法

**写法一：没有这个字段**

不写 `前置脚本`、`后置脚本` 也可以。程序里取到的是 `None`，`if pre_script:` 判断为假，直接跳过。

**写法二：空字符串**

```yaml
前置脚本: ""
后置脚本: ""
```

表示“这条用例保留前后置的位置，但暂时什么都不做”。本节的 `后置脚本` 就是这种写法。

**写法三：列表，可以有多个动作**

```yaml
前置脚本:
  - "context.update({'name': 'youer'})"
  - "context.update({'age': 18})"
```

执行顺序就是列表顺序：先放 `name`，再放 `age`。

**重点**：多个动作一定要写成**列表**（前面有 `-`），不能直接写成一整段字符串。

### 3.3 为什么脚本外面要用双引号

```yaml
前置脚本:
  - "context.update({'name': 'youer'})"
```

这条脚本里面有单引号 `'name'`。YAML 里外面再套单引号就会冲突，所以外面用双引号：

```text
外层：YAML 的双引号
内层：Python 字典的单引号
```

### 3.4 用例步骤里怎么用前置脚本的数据

前置脚本准备的是：

```text
name = youer
```

用例步骤里就能直接写：

```yaml
请求数据:
  accounts: '{{name}}'
```

`{{name}}` 会在步骤渲染时被替换成 `youer`。

## 4. run_script.py：脚本到底怎么被执行

文件位置：

```text
HAT/extend/script/run_script.py
```

完整代码：

```python
def exec_script(script, context):
    if script is None:
        return

    exec(script, {'context': context})
```

### 4.1 逐行解释

```python
def exec_script(script, context):
```

定义一个函数，接收两个参数：

- `script`：要执行的脚本，是一个字符串
- `context`：全局变量字典

```python
    if script is None:
        return
```

如果脚本是 `None`，什么都不做，直接返回，防止报错。

```python
    exec(script, {'context': context})
```

把 `script` 当代码执行。

### 4.2 `{'context': context}` 是什么意思

`exec` 的第二个参数是**全局命名空间**，也就是“这段代码能认识哪些变量”。

这里只给它一个变量：

```python
{'context': context}
```

意思是：

```text
这段脚本里，只用 context 这个变量
```

所以脚本里可以直接写 `context.update(...)`，因为 `context` 就是从这里传进去的。

例如：

```python
exec("print(context)", {'context': {'name': 'youer'}})
```

输出：

```text
{'name': 'youer'}
```

### 4.3 为什么脚本里改 context，全局变量就变了

关键在这里：

```python
run_script.exec_script(script, g_context().show_dict())
```

传进去的不是复制的字典，而是**全局变量字典本身**。

`show_dict()` 返回的就是 `_dic` 自己。所以：

```text
脚本里的 context -> _dic -> 全局变量
```

脚本里执行：

```python
context.update({'name': 'youer'})
```

等于：

```text
全局变量里多了一条 name = youer
```

### 4.4 脚本里能写什么

只要是合法 Python 代码都能写。例如：

```yaml
前置脚本:
  - "context.update({'phone': '13800000000'})"
  - "context.update({'token': 'abc123'})"
```

但因为 `exec` 是“把字符串当代码执行”，能力很大，风险也大。所以：

**只执行自己写的、可信的 YAML 用例文件，不要执行来路不明的脚本字符串。**

## 5. TestRunner.py 完整代码

文件位置：

```text
HAT/core/TestRunner.py
```

完整代码：

```python
import copy
import sys

import allure
import pytest
import requests
from tqdm import tqdm

from HAT.core.globalContext import g_context
from HAT.extend.script import run_script
from HAT.keywords.api_keywords import Keywords
from HAT.parse.YamlCaseParser import load_context_from_yaml, readYaml
from HAT.utils.VarRender import refresh


class TestRunner:
    load_context_from_yaml(r'./examples/api-cases-yaml/')
    data = readYaml(r'./examples/api-cases-yaml/login.yaml')

    @pytest.mark.parametrize('caseinfo', data)
    def test_case_exceute(self, caseinfo):
        keywords = Keywords(requests)
        base_info = caseinfo.get('基础配置', {})

        allure.dynamic.parameter('caseinfo', '')
        allure.dynamic.feature(base_info.get('一级模块', '默认模块'))
        allure.dynamic.story(base_info.get('二级模块', '默认模块'))
        allure.dynamic.title(base_info.get('用例标题', '默认用例标题'))

        local_context = caseinfo.get('local_context', {})
        context = copy.deepcopy(g_context().show_dict())
        context.update(local_context)

        pre_script = refresh(caseinfo.get('前置脚本', None), context)
        print('前置脚本数据', pre_script)
        print('没有更新全局变量', g_context().show_dict())
        if pre_script:
            for script in eval(pre_script):
                run_script.exec_script(script, g_context().show_dict())
                print('更新全局变量', g_context().show_dict())

        steps = caseinfo.get('用例步骤', None)
        with tqdm(total=len(steps), desc='开始执行') as pbar:
            for step in steps:
                step_name = list(step.keys())[0]
                step_value = list(step.values())[0]
                print('没有渲染之前的用例数据', step_value)
                pbar.set_description(f'{base_info.get("用例标题")}-当前步骤:{step_name}')
                pbar.update(1)

                with allure.step(step_name):
                    key = step_value['操作类型']
                    context = copy.deepcopy(g_context().show_dict())
                    step_value = eval(refresh(step_value, context))
                    print('渲染之后的用例数据', step_value)

                    try:
                        key_func = keywords.__getattribute__(key)
                    except AttributeError:
                        sys.path.append('./HAT/key_dir')
                        module = __import__(key)
                        class_ = getattr(module, key)
                        key_func = class_(requests).__getattribute__(key)
                    except Exception as e:
                        raise e

                    key_func(**step_value)

        local_context = caseinfo.get('local_context', {})
        context = copy.deepcopy(g_context().show_dict())
        context.update(local_context)

        post_script = refresh(caseinfo.get('后置脚本', None), context)
        print('后置脚本', post_script)
        if post_script:
            for script in eval(post_script):
                run_script.exec_script(script, g_context().show_dict())
```

### 5.1 环境和用例在类里加载

```python
class TestRunner:
    load_context_from_yaml(r'./examples/api-cases-yaml/')
    data = readYaml(r'./examples/api-cases-yaml/login.yaml')
```

这两行写在类里面、方法外面。Python 加载这个类的时候就会执行：

1. 读取 `context.yaml`，把 URL 放进全局变量
2. 读取 `login.yaml`，得到用例数据 `data`

好处是等 `test_case_exceute` 跑起来时，全局变量已经准备好了。

> 上一节这两行写在文件最外面（模块级），本节挪到了类里面。作用一样，都是“先执行、后使用”。

### 5.2 复制一份全局变量：为什么要 deepcopy

```python
context = copy.deepcopy(g_context().show_dict())
```

这里有三个写法要分清：

| 写法 | 含义 |
|---|---|
| `g_context().show_dict()` | 拿到全局变量字典**本身** |
| `copy.copy(...)` | 浅拷贝：只复制最外面一层 |
| `copy.deepcopy(...)` | 深拷贝：里里外外全部复制成新的 |

为什么要复制？因为渲染的时候只是“读”全局变量，不想因为渲染而改动全局变量。

`deepcopy` 保证：

```text
渲染用的字典是副本
全局变量还是原来的样子
```

运行时会打印这一行来证明：

```python
print('没有更新全局变量', g_context().show_dict())
```

### 5.3 local_context 是干什么的

```python
local_context = caseinfo.get('local_context', {})
context = copy.deepcopy(g_context().show_dict())
context.update(local_context)
```

`local_context` 是“**只属于这一条用例的临时变量**”。

- `g_context`：所有用例共享的全局变量
- `local_context`：这一条用例自己的变量

本节 `login.yaml` 里没有写 `local_context`，所以取到的是空字典 `{}`，`update` 等于什么都没加。这是给后面的**数据驱动**（一条用例跑多组数据）预留的位置。

### 5.4 前置脚本：三步走

**第一步，渲染：**

```python
pre_script = refresh(caseinfo.get('前置脚本', None), context)
print('前置脚本数据', pre_script)
```

`前置脚本` 从 YAML 读出来是一个**列表**：

```python
["context.update({'name': 'youer'})"]
```

`refresh` 遇到列表会先 `json.dumps` 转成字符串，再用 Jinja2 渲染。得到的还是字符串，打印出来是：

```text
前置脚本数据 ["context.update({'name': 'youer'})"]
```

**第二步，还原成列表：**

```python
if pre_script:
    for script in eval(pre_script):
```

`eval` 把字符串还原成列表：

```python
["context.update({'name': 'youer'})"]
```

然后 `for script in ...` 一条一条取出来。

**第三步，执行：**

```python
        run_script.exec_script(script, g_context().show_dict())
        print('更新全局变量', g_context().show_dict())
```

每条脚本执行完就打一次全局变量，方便观察：

```text
更新全局变量 {'URL': 'http://shop-xo.hctestedu.com', 'name': 'youer'}
```

**注意**：这里传的是 `g_context().show_dict()`，是全局变量本身，所以脚本里的修改会真正生效。

### 5.5 用例步骤循环

```python
steps = caseinfo.get('用例步骤', None)
with tqdm(total=len(steps), desc='开始执行') as pbar:
    for step in steps:
        step_name = list(step.keys())[0]
        step_value = list(step.values())[0]
```

`step` 长这样：

```python
{
    "发送登陆接口": {
        "操作类型": "发送请求POST",
        "请求地址": "{{URL}}",
        ...
    }
}
```

- `list(step.keys())[0]` 取到 `发送登陆接口`，也就是步骤名
- `list(step.values())[0]` 取到里面的字典，也就是步骤内容

`tqdm` 负责显示进度条：

```text
开始执行: 100%|██████████| 1/1 [00:00<00:00,  8.32it/s]
```

`pbar.set_description(...)` 还能把当前步骤名显示在进度条前面：

```text
商城登录用例标题-当前步骤:发送登陆接口
```

### 5.6 渲染步骤数据

```python
context = copy.deepcopy(g_context().show_dict())
step_value = eval(refresh(step_value, context))
print('渲染之后的用例数据', step_value)
```

注意这里是**每一个步骤都重新复制一次**全局变量。

为什么？因为前置脚本刚刚改了全局变量，这一步要拿到最新的。

渲染前后对比：

```text
渲染之前：
{'操作类型': '发送请求POST', '请求地址': '{{URL}}', '请求数据': {'accounts': '{{name}}', ...}}

渲染之后：
{'操作类型': '发送请求POST', '请求地址': 'http://shop-xo.hctestedu.com', '请求数据': {'accounts': 'youer', ...}}
```

可以看到 `{{URL}}` 和 `{{name}}` 都被替换掉了。

### 5.7 动态找关键字方法

```python
try:
    key_func = keywords.__getattribute__(key)
except AttributeError:
    sys.path.append('./HAT/key_dir')
    module = __import__(key)
    class_ = getattr(module, key)
    key_func = class_(requests).__getattribute__(key)
```

先在 `Keywords` 类里找 `发送请求POST` 这个方法。

如果找不到（抛 `AttributeError`），就去 `HAT/key_dir` 文件夹里找一个同名文件：

```text
HAT/key_dir/发送请求POST.py
```

然后导入它、拿到同名类、再拿到同名方法。这样以后新关键字既可以写在 `api_keywords.py` 里，也可以单独放成 `key_dir` 下的一个文件。

调用方式还是：

```python
key_func(**step_value)
```

`**step_value` 会把字典展开成一个个关键字参数。

### 5.8 后置脚本

```python
post_script = refresh(caseinfo.get('后置脚本', None), context)
print('后置脚本', post_script)
if post_script:
    for script in eval(post_script):
        run_script.exec_script(script, g_context().show_dict())
```

和前置脚本是同一套流程，只是位置换到了所有步骤跑完之后。

本节 `login.yaml` 里写的是：

```yaml
后置脚本: ""
```

所以 `post_script` 是空字符串，`if post_script:` 判断为假，什么都不执行。打印出来是：

```text
后置脚本
```

## 7. 三个新手最想问的问题

### 7.1 前置脚本里的 context，和 TestRunner 里的 context 是同一个吗

**变量名一样，但不是同一份数据。**

| 位置 | 是什么 |
|---|---|
| `TestRunner` 里的 `context` | `g_context().show_dict()` 的**深拷贝副本**，只用来渲染 |
| 传给 `exec_script` 的 `g_context().show_dict()` | 全局变量字典**本身**，脚本改动会真正生效 |

所以你会看到：

```text
执行前置脚本之前，全局变量没有 name
执行之后，全局变量有了 name
```

### 7.2 为什么渲染要用副本，执行脚本要用本体

因为两件事的目的不一样：

```text
渲染     = 只读 -> 用副本，避免污染全局变量
执行脚本 = 要写 -> 用本体，让改动生效
```

### 7.3 为什么这一节把 json.loads 换成了 eval

上一节渲染完是用 `json.loads` 还原数据的：

```python
step_value = json.loads(rendered)
```

这一节换成了 `eval`：

```python
step_value = eval(refresh(step_value, context))
```

原因是 `eval` 按 **Python 字面量**解析，比 JSON 更宽松：

| 字符串 | `json.loads` | `eval` |
|---|---|---|
| `"{'a': 1}"` | 报错 | `{'a': 1}` |
| `'{"a": 1,}'` | 报错 | `{'a': 1}` |
| `'{"a": None}'` | 报错 | `{'a': None}` |
| `'{"a": True}'` | 报错 | `{'a': True}` |

YAML 里写的脚本本身就是 Python 写法（单引号、字典），用 `eval` 不容易因为“不是标准 JSON”而报错。

**但一定要记住代价**：`eval` 和 `exec` 一样，会真的执行字符串里的代码。所以只能用在可信的用例文件上，绝不能把用户输入直接丢给它们。

## 9. 常见报错和排查方法

### 9.1 `FileNotFoundError: ...context.yaml`

原因通常是：

- 当前运行目录不对
- `examples/api-cases-yaml/context.yaml` 不存在

排查：

```powershell
Get-ChildItem examples\api-cases-yaml
```

### 9.2 `TypeError: 'NoneType' object is not iterable`

多半是脚本没有写成列表。

错误写法：

```yaml
前置脚本: "context.update({'name': 'youer'})"
```

正确写法：

```yaml
前置脚本:
  - "context.update({'name': 'youer'})"
```

为什么？`eval("context.update({...})")` 的结果是 `None`（`update` 没有返回值），`for script in None` 就会报错。

### 9.3 前置脚本执行了，但用例里 `{{name}}` 没变成 youer

排查顺序：

1. 前置脚本里写的键是不是 `name`？用例里是不是也写 `name`？大小写要完全一样。
2. 用例步骤里是不是写成了 `'{{name}}'`（要加引号）。
3. 看 `更新全局变量` 这行打印，确认 `name` 真的进去了。

### 9.4 `NameError: name 'context' is not defined`

说明脚本执行时没有拿到 `context`。

检查 `run_script.py` 里是不是这样写的：

```python
exec(script, {'context': context})
```

如果写成 `exec(script)`，脚本里就找不到 `context`。

### 9.5 渲染之后请求地址变成空字符串

`context` 里没有这个变量时，Jinja2 默认会把它渲染成空字符串。

排查：

- `context.yaml` 里是不是写了 `URL`
- 大小写是否一致（`URL` 和 `url` 不是同一个变量）

### 9.6 脚本报 `SyntaxError`

说明脚本字符串本身不是合法 Python 代码。常见原因：

- YAML 里的引号嵌套写错
- 少了一个括号
- 用了中文符号（比如中文引号 `’`、中文括号 `（）`）

建议先在 Python 里单独试一下这句脚本能不能跑：

```python
context = {}
exec("context.update({'name': 'youer'})", {'context': context})
print(context)
```

输出：

```text
{'name': 'youer'}
```

### 9.7 `KeyError: '操作类型'`

某个步骤里没写 `操作类型`，检查 YAML：

```yaml
操作类型: 发送请求POST
```

## 10. 本节重点记忆

| 名称 | 作用 |
|---|---|
| `前置脚本` | 用例执行前准备数据（setup） |
| `后置脚本` | 用例执行后清理数据（teardown） |
| `context` | 全局变量字典，前后置脚本靠它读写数据 |
| `context.update({...})` | 往全局变量里批量加数据 |
| `exec` | 把字符串当代码执行，没有返回值 |
| `eval` | 把字符串当表达式求值，有返回值 |
| `exec_script` | 框架里执行脚本的函数 |
| `{'context': context}` | 让脚本里能直接使用 `context` 这个名字 |
| `copy.deepcopy` | 深拷贝，渲染时用副本，不污染全局变量 |
| `local_context` | 只属于当前用例的临时变量（为数据驱动预留） |
| `tqdm` | 进度条 |

执行顺序一句话：

> 全局变量 -> 前置脚本 -> 渲染步骤 -> 接口请求 -> 后置脚本

本节一句话总结：

> 把“用例执行前要准备、执行后要清理”的动作，用 Python 脚本写进 YAML；脚本通过 `context` 读写全局变量，用例步骤再用 `{{变量名}}` 把数据取出来。
