# 第08课 课堂笔记｜YAML多用例管理机制（8月31日）

> 本节目标：让框架自动把一个文件夹里的所有 YAML 用例都读进来、按顺序跑完；同时解决一个真实问题——登录接口拿到的 token，怎么传给下一个加购物车的接口。

---

## 0. 先用一句话理解本节

上一节的框架有一个很实际的问题：**一次只能读一个 YAML 文件**。

上一节的 `TestRunner.py` 里写死了这一行：

```python
data = readYaml(r'./examples/api-cases-yaml/login.yaml')
```

你新写了一个用例，就得回来改这行代码。用例一多，这个方法就不行了。

本节要解决两件事：

```text
第一件：把文件夹里所有 YAML 用例都读进来，一次性跑完
第二件：上一条用例拿到的数据，传给下一条用例用
```

第二件事叫**接口关联**。为什么需要它？因为登录接口返回的 token，只存在于登录的响应里：

```text
1_login.yaml   -> 发登录请求 -> 响应里有 token
2_addcard.yaml -> 发加购物车请求 -> 需要带上这个 token
```

token 在另一个文件里、另一次请求里，不会自己跑到加购物车接口上去。

一句话总结：

```text
多用例管理：一个文件夹里的 YAML 全部当用例跑
接口关联  ：上一步产生的数据，存进全局变量，下一步取出来用
```

## 1. 新手先认识 6 个词

### 1.1 多用例管理

以前是“一条用例一个文件，还要手动告诉程序读哪一个”。

现在是“把用例都放进一个文件夹，程序自己去找、自己去读、自己排顺序”。

### 1.2 用例识别规则（命名规范）

文件夹里除了用例文件，还有 `context.yaml` 这种配置文件。程序怎么知道哪个是哪个？

靠**文件名**。本节的规则是：

```text
数字开头_名字.yaml   -> 是用例
其它                 -> 不是用例，不读
```

所以：

```text
1_login.yaml    -> 是用例
2_addcard.yaml  -> 是用例
context.yaml    -> 不是用例（它是环境配置）
```

### 1.3 接口关联

定义很简单：

```text
上一个接口的返回结果里，有下一个接口需要的数据
-> 先把它取出来存好
-> 下一个接口再去取出来用
```

生活中也好理解：你去银行先办卡（拿到卡号），再去取钱（要用卡号）。卡号不会自动出现在取款机上，得你自己带过去。

### 1.4 token

`token` 可以理解成“**登录成功后发给你的一张通行证**”。

登录接口的响应里会带一个 token，长这样：

```json
{
  "msg": "登录成功",
  "code": 0,
  "data": {
    "id": "1580",
    "username": "youer",
    "token": "0bc5caeacee16e3d943cbcdc7a28dde7"
  }
}
```

后面的接口（比如加购物车）要证明“我已经登录过了”，所以要在请求里带上这个 token。

### 1.5 JSONPath

JSONPath 是“**从 JSON 里按规则找数据**”的写法。第 02 课学过，这里复习几个符号：

| 符号 | 含义 | 例子 |
|---|---|---|
| `$` | 根节点，表示“从这个 JSON 的最外层开始找” | `$.msg` |
| `.` | 下一层 | `$.data.token` |
| `..` | 递归找，不管嵌套多深 | `$..token` |
| `[数字]` | 取第几个 | 后面讲“下标”时用到 |

我拿真实的登录响应实测了一遍，结果如下（**注意每个结果都是一个列表**）：

| 表达式 | 含义 | 实测结果 |
|---|---|---|
| `$..token` | 递归找所有叫 token 的字段 | `['0bc5caeacee16e3d943cbcdc7a28dde7']` |
| `$.data.token` | 按路径一层层取 | `['0bc5caeacee16e3d943cbcdc7a28dde7']` |
| `$.msg` | 取最外层的 msg | `['登录成功']` |
| `$.data.id` | 取 data 里的 id | `['1580']` |
| `$.code` | 取 code | `[0]` |
| `$.data.not_exist` | 取一个不存在的字段 | `False` |

最后一行很重要：**找不到的时候返回的不是空列表，而是 `False`**，这是 `jsonpath` 这个库的行为，代码里就是靠它判断有没有取到值。

### 1.6 全局变量（复习第 06、07 课）

框架里所有用例共享的一个字典，存在 `g_context` 里：

```python
g_context().set_dict('my_token', 'xxx')   # 存进去
g_context().get_dict('my_token')          # 取出来
g_context().show_dict()                   # 看全部
```

本节就是用它来把 token 从第一条用例传到第二条用例。

## 2. 整体执行流程

先看全局，不急着看代码细节：

```text
1. 读取 context.yaml，把 URL 放进全局变量
2. 列出用例文件夹里的所有文件
3. 只挑出「数字开头_名字.yaml」的文件
4. 按数字从小到大排序              <- 顺序就是执行顺序
5. 依次读进内存，得到一个列表
6. 交给 pytest 参数化，有几个文件就生成几条用例
7. 第 1 条用例：发登录请求 -> 把响应存进全局变量 -> 提取 token 存进全局变量
8. 第 2 条用例：渲染步骤时用 {{my_token}} 取出 token -> 发加购物车请求
```

对应到文件和函数：

```text
context.yaml
  -> YamlCaseParser.load_context_from_yaml()
  -> g_context().set_by_dict()

用例文件夹
  -> YamlCaseParser.load_yaml_files()
  -> 过滤 + 排序 + 逐个读取
  -> 返回 [用例1, 用例2]

TestRunner
  -> pytest.mark.parametrize('caseinfo', data)
  -> 几条用例就执行几次

登录响应
  -> Keywords.发送请求POST() 里 set_dict('响应结果', response)

提取数据
  -> Keywords.提取数据JSON()
  -> jsonpath 找到 token
  -> set_dict('my_token', token)

加购物车
  -> {{my_token}} 渲染成真实 token
  -> 请求带上 token
```

**记住两个顺序**：

```text
文件顺序：数字小的先跑
数据顺序：谁产生数据，谁先跑
```

## 3. YAML 里怎么写：1_login.yaml 和 2_addcard.yaml

文件位置：

```text
examples/api-cases-yaml/
```

### 3.1 和上一节比，多了什么

**文件名变了**：从 `login.yaml` 变成 `1_login.yaml`，前面加了数字。

**多了一个用例文件**：新增 `2_addcard.yaml`。

**登录用例多了一个步骤**：用来提取 token。

### 3.2 两个文件的完整内容

`1_login.yaml`：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录用例标题
  一级模块: 登录模块
  二级模块: 登录功能

前置脚本:
  - "context.update({'name': 'youer'})"
后置脚本: ""

用例步骤:
  - 发送登陆接口:
      操作类型: 发送请求POST
      请求地址: '{{URL}}'
      URL参数:
        s: /api/user/login
        application: app
        application_client_type: weixin
      请求数据:
        accounts: '{{name}}'
        pwd: '123456'
        type: username

  - 提取响应数据token:
      操作类型: 提取数据JSON
      表达式: $..token
      下标: 0
      变量名: my_token
```

`2_addcard.yaml`：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 购物车用例标题
  一级模块: 购物车模块
  二级模块: 购物车功能

用例步骤:
  - 发送购物车接口:
      操作类型: 发送请求POST
      请求地址: '{{URL}}'
      URL参数:
        s: api/cart/save
        application: app
        application_client_type: weixin
        token: '{{my_token}}'
      请求数据:
        goods_id: '2'
        stock: '1'
```

### 3.3 用例文件名就是执行顺序

两个文件名前面的 `1` 和 `2`，决定了谁先跑：

```text
1_login.yaml   先跑：登录，然后提取 token
2_addcard.yaml 后跑：带着 token 加购物车
```

这个顺序不是随便起的。**数字 1 负责产生数据，数字 2 负责使用数据**。顺序反了，加购物车就拿不到 token。

### 3.4 提取步骤怎么写

`1_login.yaml` 的第二个步骤：

```yaml
  - 提取响应数据token:
      操作类型: 提取数据JSON
      表达式: $..token
      下标: 0
      变量名: my_token
```

注意：**提取也是一个“用例步骤”**，和发送请求是平级的。它的“操作类型”是 `提取数据JSON`，框架就会去找 `Keywords` 里同名的方法。

四个参数的作用：

```text
操作类型 -> 要调用哪个关键字方法
表达式   -> 从响应 JSON 里怎么找
下标     -> 找到多个时取第几个（不写默认 0）
变量名   -> 取到的值存成什么名字，后面用 {{名字}} 取
```

## 4. YamlCaseParser.py：批量读取用例

文件位置：

```text
HAT/parse/YamlCaseParser.py
```

### 4.1 完整代码

```python
def load_yaml_files(file_path):
    yaml_case_infos = []
    suite_folder = os.path.join(file_path)
    load_context_from_yaml(file_path)

    file_names = [
        (int(f.split('_')[0]), f)
        for f in os.listdir(suite_folder)
        if f.endswith('.yaml') and f.split('_')[0].isdigit()
    ]
    file_names.sort()
    file_names = [f[-1] for f in file_names]

    for file_name in file_names:
        file_path = os.path.join(suite_folder, file_name)
        with open(file_path, 'r', encoding='utf-8') as file:
            caseinfo = yaml.full_load(file)
            yaml_case_infos.append(caseinfo)

    return yaml_case_infos
```

### 4.2 逐行解释

```python
yaml_case_infos = []
```

新建一个空列表，一会儿把所有用例装进去。

```python
suite_folder = os.path.join(file_path)
```

`os.path.join` 是“把路径拼起来”的函数。这里只传了一个参数，所以结果和原来一样，就是用例文件夹的路径。

```python
load_context_from_yaml(file_path)
```

这就是上一节的函数，把 `context.yaml` 里的 `URL` 放进全局变量。

> 小细节：`TestRunner` 里其实也单独调用了一次 `load_context_from_yaml`，所以 `context.yaml` 被读了两次，启动时“全局变量”会打印两遍。重复读没有副作用，但看到两遍别以为是 bug。

```python
file_names = [
    (int(f.split('_')[0]), f)
    for f in os.listdir(suite_folder)
    if f.endswith('.yaml') and f.split('_')[0].isdigit()
]
```

这是**列表推导式**，筛选出符合条件的文件。下面单独讲。

```python
file_names.sort()
file_names = [f[-1] for f in file_names]
```

排序，然后把文件名取回来。下面单独讲。

```python
for file_name in file_names:
    file_path = os.path.join(suite_folder, file_name)
    with open(file_path, 'r', encoding='utf-8') as file:
        caseinfo = yaml.full_load(file)
        yaml_case_infos.append(caseinfo)
```

循环里做三件事：

1. `os.path.join` 把文件夹路径和文件名拼成完整路径，比如 `./examples/api-cases-yaml/1_login.yaml`
2. 打开文件，用 `yaml.full_load` 把 YAML 文本变成 Python 字典
3. `append` 把这条用例装进结果列表

`encoding='utf-8'` 是为了正确读取中文，不写容易乱码。

```python
return yaml_case_infos
```

返回的是一个**列表，里面装着每个 YAML 文件读出来的字典**：

```python
[ {1_login 的用例数据}, {2_addcard 的用例数据} ]
```

有几个符合规则的文件，列表里就有几个元素。

### 4.3 列表推导式拆解

新手最容易卡在这几行。它是**列表推导式**，可以理解成“一边遍历、一边筛选、一边加工，最后得到一个列表”。

看不懂的时候，把它还原成普通写法，意思完全一样：

```python
file_names = []
for f in os.listdir(suite_folder):
    if f.endswith('.yaml') and f.split('_')[0].isdigit():
        file_names.append((int(f.split('_')[0]), f))
```

拆开看三个部分：

**① `os.listdir(suite_folder)`**

列出文件夹里的**所有文件名**，得到的是文件名，不是完整路径：

```text
['1_login.yaml', '2_addcard.yaml', 'context.yaml', '__init__.py']
```

**② `if f.endswith('.yaml') and f.split('_')[0].isdigit()`**

这是筛选条件，两个条件必须同时满足（`and`）：

- `f.endswith('.yaml')`：文件名以 `.yaml` 结尾
- `f.split('_')[0].isdigit()`：用下划线切开，取第一段，判断是不是纯数字

`split('_')` 是“按某个字符把字符串切开”：

```text
'1_login.yaml'.split('_')  -> ['1', 'login.yaml']       取 [0] 得到 '1'             是数字 v
'context.yaml'.split('_')  -> ['context.yaml']          取 [0] 得到 'context.yaml'  不是数字 x
```

我把各种文件名都试了一遍，结果如下：

| 文件名 | 以 .yaml 结尾 | 下划线前是数字 | 会被当用例吗 |
|---|---|---|---|
| `1_login.yaml` | 是 | 是 | 是 |
| `2_addcard.yaml` | 是 | 是 | 是 |
| `context.yaml` | 是 | 否 | 否 |
| `__init__.py` | 否 | 否 | 否 |
| `1login.yaml` | 是 | 否 | 否 |
| `12.yaml` | 是 | 否 | 否 |
| `abc_1.yaml` | 是 | 否 | 否 |
| `3_test.YAML` | 否（大小写敏感） | 是 | 否 |

**这里有个容易踩的坑**：口诀说是“数字开头”，但代码实际要求的是“**下划线前面的部分全是数字**”。所以 `1login.yaml` 这种“数字开头但没有下划线”的名字，是不会被读取的。名字一定要写成 `数字_名字.yaml`。

**③ `(int(f.split('_')[0]), f)`**

把数字和文件名打包成一个**元组**，也就是一对数据：

```text
'1_login.yaml'   -> (1, '1_login.yaml')
'2_addcard.yaml' -> (2, '2_addcard.yaml')
```

为什么要 `int(...)` 转换？为了排序，下面讲。

### 4.4 为什么要 int()

因为列表里装的是元组 `(数字, 文件名)`，`sort()` 会**先比数字**，数字小的排前面。

如果不转成数字，按字符串排就出问题了：

```text
按字符串排序：10_x.yaml、1_login.yaml、2_addcard.yaml   <- 错的
按数字排序：  1_login.yaml、2_addcard.yaml、10_x.yaml   <- 对的
```

字符串比较是“一个字符一个字符比”：`'10_x'` 和 `'1_login'` 的第一个字符都是 `1`，于是比第二个字符，`0` 比 `_` 小，所以 `10_x.yaml` 反而排到了最前面。用例一旦超过 9 条，顺序就全乱了。

排完序之后：

```python
file_names = [f[-1] for f in file_names]
```

`f[-1]` 表示取元组的最后一个元素，也就是把文件名取回来，丢掉数字：

```text
[(1, '1_login.yaml'), (2, '2_addcard.yaml')]
  -> ['1_login.yaml', '2_addcard.yaml']
```

### 4.5 和上一节 readYaml 的区别

| | `readYaml`（上一节） | `load_yaml_files`（本节） |
|---|---|---|
| 读几个文件 | 1 个 | 文件夹里所有符合规则的 |
| 要写路径吗 | 要，而且写死文件名 | 只要给文件夹路径 |
| 新增用例 | 要改代码 | 放进去就行 |
| 顺序 | 无所谓 | 按数字前缀排序 |
| 返回值 | `[1条用例]` | `[用例1, 用例2, ...]` |

> `readYaml` 这个函数本节还留在文件里，但 `TestRunner` 已经不用它了。

## 5. api_keywords.py：接口关联的两个关键字

文件位置：

```text
HAT/keywords/api_keywords.py
```

接口关联要靠两个关键字配合：一个负责“把响应存起来”，一个负责“从响应里把值抠出来”。

### 5.1 第一步：把响应存进全局变量

在 `发送请求POST` 里加了一行：

```python
    try:
        response = self.request.request('post', **requests_data)
        print('发送结果', response.json())
        g_context().set_dict('响应结果', response)   # 本节新增
        return response
```

意思很直白：**每发一次 POST 请求，就把响应对象存到全局变量里，键名固定叫 `响应结果`**。

为什么要存整个 `response`，不直接存 `response.json()`？

因为 `response` 对象上还有状态码、响应头等信息，存整个对象以后想用什么都有；需要 JSON 的时候再调 `.json()` 即可。

### 5.2 第二步：提取数据JSON

完整代码：

```python
    @allure.step('提取数据JSON')
    def 提取数据JSON(self, **kwargs):
        expression = kwargs.get('表达式', None)
        index = kwargs.get('下标', 0)
        if index is None:
            index = 0

        response = g_context().get_dict('响应结果').json()
        result = jsonpath.jsonpath(response, expression)
        if not result:
            raise Exception(f'没有找到对应的数据:{expression}')

        ex_data = result[index]
        g_context().set_dict(kwargs['变量名'], ex_data)
        print('全局变量中有没有token值', g_context().show_dict())
```

逐行解释：

```python
expression = kwargs.get('表达式', None)
index = kwargs.get('下标', 0)
if index is None:
    index = 0
```

从 YAML 传进来的参数里取这三个东西。`kwargs.get('下标', 0)` 的意思是“有下标就用，没有就默认 0”。后面那句 `if index is None` 是为了防止 YAML 里写了 `下标:` 但没写值（那样取出来是 `None`）。

```python
response = g_context().get_dict('响应结果').json()
```

从全局变量里取出 `响应结果`，再调 `.json()` 把响应变成 Python 字典。

如果之前没发过请求，`get_dict('响应结果')` 返回的是 `None`，`None.json()` 就会报错：

```text
AttributeError: 'NoneType' object has no attribute 'json'
```

```python
result = jsonpath.jsonpath(response, expression)
```

`jsonpath.jsonpath(要查找的字典, 表达式)`，返回一个**列表**。

`$..token` 在这种响应上的结果就是：

```text
['0bc5caeacee16e3d943cbcdc7a28dde7']
```

```python
if not result:
    raise Exception(f'没有找到对应的数据:{expression}')
```

这里用 `if not result` 而不是 `if result == []`，是因为 `jsonpath` 找不到时返回的是 `False`（前面实测过），用 `not` 一起兜住。报错信息里带上表达式，一眼就知道是哪个表达式写错了。

```python
ex_data = result[index]
```

`result` 是列表，用“下标”取其中一个。`$..token` 递归查找时，如果响应里有多个 token 字段，列表里就会有多个值，这时“下标”就派上用场了。

```python
g_context().set_dict(kwargs['变量名'], ex_data)
```

`变量名` 是 YAML 里写好的 `my_token`，所以全局变量里就多了一条：

```text
my_token = '0bc5caeacee16e3d943cbcdc7a28dde7'
```

注意这里用的是 `kwargs['变量名']`（中括号），不是 `.get`。因为“变量名”是必填的，不写就直接报 `KeyError`，早报错比晚报错好。

### 5.3 三个参数总结

| YAML 里的参数 | 作用 | 说明 |
|---|---|---|
| `表达式` | 从 JSON 里怎么找 | `$..token` 递归找，`$.data.id` 精确找 |
| `下标` | 找到多个时取第几个 | 不写默认 0 |
| `变量名` | 取到的值存成什么名字 | 下个接口用 `{{名字}}` 取 |

### 5.4 注意：只有 POST 存了响应

本节只有 `发送请求POST` 里写了：

```python
g_context().set_dict('响应结果', response)
```

`发送请求GET` 里**没有**这一行。所以这个版本的“提取数据JSON”只能提取 POST 请求的响应。如果以后要提取 GET 的响应，得自己在 `发送请求GET` 里也加一行。

## 6. TestRunner.py 的变化

文件位置：

```text
HAT/core/TestRunner.py
```

这一节 `TestRunner` 只改了两处，其余部分和上一节一样。

### 6.1 导入换了

```python
from HAT.parse.YamlCaseParser import load_context_from_yaml, load_yaml_files
```

以前导入的是 `readYaml`，现在换成 `load_yaml_files`。

### 6.2 读用例的方式换了

```python
class TestRunner:
    load_context_from_yaml(r'./examples/api-cases-yaml/')
    data = load_yaml_files(r'./examples/api-cases-yaml/')
```

`data` 现在是一个**列表**，里面是两条用例。

### 6.3 pytest 自动变成两条用例

```python
@pytest.mark.parametrize('caseinfo', data)
def test_case_exceute(self, caseinfo):
```

`parametrize` 的作用是“把列表里的每个元素都跑一遍”。`data` 里有 2 个元素，就生成 2 条测试用例：

```text
TestRunner::test_case_exceute[caseinfo0]   <- 1_login.yaml
TestRunner::test_case_exceute[caseinfo1]   <- 2_addcard.yaml
```

以后往文件夹里再放一个 `3_xxx.yaml`，不用改任何代码，自动就多一条用例。

### 6.4 数据怎么跨用例传

关键在 `g_context` 的 `_dic` 是**类变量**（第 06 课讲过）：

```python
class g_context:
    _dic = {}
```

它属于类，不属于某一个对象，所以：

```text
第一条用例 set_dict('my_token', ...) 写进去
第二条用例 get_dict('my_token') 还能读到
```

再加上 pytest 是在**同一个进程**里依次跑完这两条用例的，所以数据能接上。

### 6.5 其余部分和上一节一样

第 07 课的 `前置脚本` / `后置脚本` 逻辑原样保留。所以你会看到第二个用例打印的是：

```text
前置脚本数据 None
后置脚本 None
```

因为 `2_addcard.yaml` 里根本没写这两个字段，`caseinfo.get(..., None)` 取到 `None`，`if` 判断为假，直接跳过。

## 9. 常见报错和排查方法

### 9.1 `ModuleNotFoundError: No module named 'jsonpath'`

没装依赖。本节的 `requirements.txt` 新增了：

```text
jsonpath==0.82.2
```

安装：

```powershell
pip install -r requirements.txt
```

### 9.2 `AttributeError: 'NoneType' object has no attribute 'json'`

`提取数据JSON` 执行时，全局变量里没有 `响应结果`。

原因：提取步骤前面没有发过 POST 请求，或者顺序被改乱了。

排查：看打印出来的全局变量里有没有 `响应结果`。

### 9.3 `Exception: 没有找到对应的数据:$.token`

JSONPath 表达式没匹配到任何东西。

排查：

- 表达式写错了？`$.token` 和 `$.data.token` 是不同的路径。
- 字段名大小写对不对？`token` 和 `Token` 不是一回事。
- 先打印 `response.json()`，直接看看响应里到底有什么字段。

### 9.4 `IndexError: list index out of range`

“下标”超出了结果范围。

比如表达式只匹配到 1 个值，但下标写了 `2`（列表里只有第 0 个）。

排查：把下标改成 `0`，或者先打印一下 `result` 的长度。

### 9.5 新增的 YAML 没有被执行

检查文件名：

- 有没有数字前缀？
- 数字和下划线之间、下划线和名字之间有没有空格？
- 是不是 `.yaml` 结尾？（`.YAML` 不行）
- 分隔符是下划线 `_`，不是短横线 `-`。

对照第 4.3 节的表格逐条核一下。

### 9.6 渲染后 token 变成空字符串

说明全局变量里没有 `my_token`，Jinja2 把取不到的变量渲染成了空字符串（不会报错，所以很隐蔽）。

排查顺序：

1. 打印全局变量，确认 `my_token` 是否真的存进去了。
2. 确认提取步骤里的变量名和 `{{}}` 里的一致（`变量名: my_token` 对应 `{{my_token}}`）。
3. 确认两条用例的执行顺序没被打乱。

### 9.7 中文显示乱码

读写文件时都要带 `encoding='utf-8'`：

```python
with open(file_path, 'r', encoding='utf-8') as file:
```

运行命令时如果控制台还是乱码，可以先设置编码：

```powershell
$env:PYTHONIOENCODING='utf-8'
```

## 10. 本节重点记忆

| 名称 | 作用 |
|---|---|
| 用例识别规则 | `数字开头_名字.yaml`，下划线前的部分必须全是数字 |
| `os.listdir` | 列出文件夹里的所有文件名 |
| `f.endswith('.yaml')` | 判断文件名是不是 YAML |
| `f.split('_')[0].isdigit()` | 判断下划线前是不是数字 |
| 列表推导式 | 一边遍历一边筛选一边加工，得到新列表 |
| `int(...)` | 转成数字，为了按数字排序 |
| `(数字, 文件名)` 元组 | 把编号和文件名打包，方便排序 |
| `sort()` | 排序，决定用例执行顺序 |
| `load_yaml_files` | 批量加载整个文件夹的用例 |
| `parametrize` | 有几个用例就跑几次 |
| `响应结果` | 全局变量里保存的最近一次 POST 响应 |
| `提取数据JSON` | 用 JSONPath 从响应里取值存进全局变量 |
| `表达式` / `下标` / `变量名` | 提取的三个参数 |
| `jsonpath.jsonpath()` | 返回列表；找不到返回 `False` |
| `{{my_token}}` | 下个用例把提取到的值取出来用 |

两句话总结：

> 多用例管理：给文件夹和一份命名规则，让框架自己找用例、排顺序、逐个执行。
>
> 接口关联：上一个接口的数据存进全局变量，下一个接口用 `{{变量名}}` 取出来。
