# 8月26号 · 二次接口封装（day08）

## 为什么要封装
- 每个接口都要写 requests.post/get，url、json/data、headers、params 参数各不相同，还要写异常处理，重复代码太多
- 封装的好处：一处修改，处处生效；调用更简单

## 封装思路（Keywords 类）
- 把 requests.post / requests.get 封装成两个方法：
  - `发送请求POST(**kwargs)`
  - `发送请求GET(**kwargs)`
- `__init__(self, request)`：传入 requests 或 requests.session

## 用到的知识点
- `**kwargs`：接收任意多个关键字参数，参数不写死
- `kwargs.get('请求地址', None)`：取值，取不到给默认值
- 自动区分 json / data 两种传参方式（按"请求类型"判断）
- `.lower()`：把字符串转成小写，让请求类型大小写都能识别（如 'JSON'→'json'），避免大小写不一致报错
- `requests.request('post', **请求参数字典)` == `requests.post(...)`
- 统一加 try/except 异常处理
- `**字典名`：字典解包，把字典展开成"参数名=值"传给函数
  - 如 `func(**{'url':'xxx','json':{'a':1}})` == `func(url='xxx', json={'a':1})`
  - 前提：字典的键必须是字符串，且要和函数的参数名对得上
- 字典里"没有就不放"：字典里只放当前请求实际用到的参数，展开时字典里有哪个键就传哪个参数，没有的就不传
  - 好处：同一个封装方法，有的请求传 json、有的传 data、有的带 headers，各自构造自己的字典，不用写一堆 if 判断

## __init__(self, request) 为什么能传 requests 或 requests.session
- 创建对象时括号里传什么，就自动赋值给 __init__ 的参数（如 Keywords(requests) → request 就是 requests 模块）
- Python 是动态类型：参数不限定类型，传什么类型都能接住
- 两个都能用是因为"鸭子类型"：requests 模块有 .request()，session 对象也有 .request()，调用方式一样，能用就行
- 区别：传 requests 每次请求独立（相当于新开浏览器）；传 requests.session() 会自动保持 cookie、关联登录状态

## 使用方式
```python
keyword = Keywords(requests)
res = keyword.发送请求POST(请求地址=url, 请求数据=data, 请求类型='json')
res = keyword.发送请求GET(请求地址=url)
```

## 参数说明（与 yaml 用例对应）
- 请求地址：url
- 请求数据：请求体（data 或 json）
- URL参数：params（拼在 url 后面）
- 请求头：headers
- 请求类型：'data' 或 'json'（默认 data）
