# 第01课 课堂笔记｜Requests 接口自动化库应用（8月24日）

> 本节目标：装上 `requests` 库、把 PyCharm 的虚拟环境配好，学会用 requests 发 GET 和 POST 请求，并搞清楚 `params`、`data`、`json`、`headers` 这四个参数分别放在请求的哪个位置。这是整个接口自动化的第一步。

## 0. 先用一句话理解本节

接口自动化，说白了就是**让 Python 代替你去点接口**。

平时测接口是打开工具（Postman 之类），填地址、填参数、点发送、看返回。本节要做的，是把这套动作写成 Python 代码：

```python
import requests

r = requests.get('http://shop-xo.hctestedu.com')
print(r.status_code)
```

就这几行，Python 就替你发了一次请求。

本节的路线是：

```text
装环境 -> 会发一个请求 -> 搞清楚参数放哪里 -> 为后面写框架打基础
```

其中最容易出错、也最需要一开始就搞清楚的是最后一步：`params`、`data`、`json`、`headers` 到底该写哪个。写错了，接口会返回“参数错误”，或者干脆收不到你的数据。

一句话总结：

```text
接口自动化第一步：让 Python 能发请求，并且知道每个参数该放在哪里
```

## 1. 新手先认识 6 个词

### 1.1 接口（API）

接口可以理解成“**程序之间说话的通道**”。

你打开商城 App 看到商品列表，其实是 App 去问服务器要的数据，这个“要数据”的地址就是接口。

调用一个接口，需要知道四件事：

```text
地址（URL）：找谁
请求方式   ：GET 还是 POST
参数       ：要什么、给什么
请求头     ：附加说明（用什么格式、带没带 token）
```

### 1.2 接口自动化测试

就是用代码把“发请求 → 检查返回”这套动作自动跑起来，还能生成测试报告。

本课程后面会做出的功能：

```text
通过测试用例生成测试报告
支持 YAML 和 Excel 两种格式写用例
```

### 1.3 requests 库

Python 里用来发 HTTP 请求的第三方库。有了它，你就不用自己拼 URL、拼请求体了。

### 1.4 GET 和 POST

两种最常见的请求方式：

```text
GET ：一般用来“查”，参数拼在地址后面
POST：一般用来“增删改”，参数放在请求体里
```

第 5 节会详细对比。

### 1.5 请求四要素

看懂这四个词，接口测试就懂一半了：

| 名称 | 位置 | 在 requests 里怎么写 |
|---|---|---|
| URL | 地址 | 函数的第一个参数 |
| 参数 | 拼在地址后面 | `params={...}` |
| 请求体 | 放在 body 里 | `data={...}` 或 `json={...}` |
| 请求头 | 放在 header 里 | `headers={...}` |

### 1.6 虚拟环境（venv）

可以理解成“**给每个项目单独准备一个工具箱**”。

项目 A 用 requests 2.0，项目 B 用 requests 3.0，装在同一个地方就会打架。虚拟环境让每个项目用自己那一份库，互不影响。

## 4. requests 的三种请求写法

### 4.1 通用写法：requests.request()

```python
import requests

r = requests.request('get', 'http://shop-xo.hctestedu.com')
```

第一个参数写请求方式（`get`、`post`、`put`、`delete` 等），第二个参数写地址。

好处是**请求方式可以当变量传**，以后框架里就是这样动态决定发什么请求的。

### 4.2 简写一：requests.get()

```python
import requests

r = requests.get('http://shop-xo.hctestedu.com')
```

### 4.3 简写二：requests.post()

```python
import requests

r = requests.post(
    'http://shop-xo.hctestedu.com',
    params={'s': '/api/user/login', 'application': 'app'},
    data={'accounts': 'youer', 'pwd': '123456'},
)
```

### 4.4 三种写法的关系

```text
requests.get(url)       就等于 requests.request('get', url)
requests.post(url, ...) 就等于 requests.request('post', url, ...)
```

平时用简写更省事；写框架时用 `request`，因为请求方式要从 YAML 里读出来。

### 4.5 返回结果 r 上有什么

发完请求会得到一个 `r`，常用的有：

```python
r.status_code    # 状态码，200 表示成功
r.text           # 返回的文本（字符串）
r.json()         # 把返回内容转成字典（返回的是 JSON 时才能用）
r.url            # 这次实际请求的完整地址
r.headers        # 响应头
```

## 5. GET 和 POST 的区别

### 5.1 GET：参数拼在地址后面

课上举的例子（当当登录）：

```text
/dangdang/user/login?user.email=123@qq.com&user.password=123456
```

问号 `?` 后面的部分就是参数，多个参数之间用 `&` 隔开。

### 5.2 POST：参数放在请求体里

POST 的参数不会出现在地址上，而是放在请求体（body）里，用表单或者 JSON 的格式提交。

### 5.3 对比表

| 对比项 | GET | POST |
|---|---|---|
| 参数位置 | 拼在 URL 后面 | 放在请求体 body 里 |
| 安全性 | 不够安全，数据直接暴露在地址上 | 相对安全，数据在请求体里 |
| 数据大小 | 有限制（大约 1KB） | 基本没有限制 |
| 主要用途 | 查询 | 增、删、改 |

**注意**：这里的“安全”只是相对说法。POST 的数据在网络里依然是明文，真正要安全得靠 HTTPS。

## 6. params / data / json / headers 分别放在哪里

这是本节的重点。我把这四个参数各跑了一遍，把最终发出去的请求打印出来看，结论如下。

### 6.1 params：拼在地址后面

```python
import requests

r = requests.Request(
    'GET',
    'http://shop-xo.hctestedu.com',
    params={'s': '/api/user/login', 'application': 'app'},
).prepare()

print(r.url)
print(r.body)
```

实测输出：

```text
最终 URL : http://shop-xo.hctestedu.com/?s=%2Fapi%2Fuser%2Flogin&application=app
请求体    : None
```

可以看到三件事：

- 参数被拼到了 URL 后面，用 `?` 和 `&` 连接
- 请求体是空的（`None`）
- 斜杠 `/` 变成了 `%2F`，这是 URL 编码，属于正常现象

### 6.2 data：按表单格式放进请求体

```python
r = requests.Request(
    'POST',
    'http://shop-xo.hctestedu.com',
    data={'accounts': 'youer', 'pwd': '123456'},
).prepare()

print(r.url)
print(r.body)
print(r.headers.get('Content-Type'))
```

实测输出：

```text
最终 URL : http://shop-xo.hctestedu.com/
请求体    : accounts=youer&pwd=123456
Content-Type: application/x-www-form-urlencoded
```

注意 Content-Type 自动变成了 `application/x-www-form-urlencoded`，这是**表单格式**的标记。

### 6.3 json：按 JSON 格式放进请求体

```python
r = requests.Request(
    'POST',
    'http://shop-xo.hctestedu.com',
    json={'accounts': 'youer', 'pwd': '123456'},
).prepare()

print(r.url)
print(r.body)
print(r.headers.get('Content-Type'))
```

实测输出：

```text
最终 URL : http://shop-xo.hctestedu.com/
请求体    : b'{"accounts": "youer", "pwd": "123456"}'
Content-Type: application/json
```

Content-Type 变成了 `application/json`，请求体也变成了 JSON 字符串。

### 6.4 headers：放进请求头

```python
r = requests.Request(
    'GET',
    'http://shop-xo.hctestedu.com',
    headers={'token': 'abc123', 'User-Agent': 'my-test'},
).prepare()

print(r.headers.get('token'))
print(r.headers.get('User-Agent'))
```

实测输出：

```text
abc123
my-test
```

请求头适合放这些东西：

```text
Content-Type ：告诉服务端我用什么格式发数据
token        ：身份凭证，证明我登录过了
User-Agent   ：我是什么客户端
Cookie       ：会话信息
```

### 6.5 一句话记住放哪里

```text
params  -> 放在 URL 上（问号后面）
data    -> 放在请求体里，表单格式
json    -> 放在请求体里，JSON 格式
headers -> 放在请求头里
```

**最容易犯的错**：服务端要 JSON，你却用了 `data`，结果服务端收到的是表单，就会报参数错误。判断方法是看接口文档里的 Content-Type：写 `application/json` 就用 `json=`，写 `application/x-www-form-urlencoded` 就用 `data=`。

## 8. 真实运行输出

### 8.1 一个真实的 GET 请求

```python
import requests

r = requests.get('http://shop-xo.hctestedu.com', params={'s': 'index/index'})
print('状态码:', r.status_code)
print('地址  :', r.url)
print('返回  :', r.text[:60])
```

实测输出：

```text
状态码: 200
地址  : http://shop-xo.hctestedu.com/?s=index%2Findex
返回  : <!DOCTYPE html> <html> <head> <meta charset="utf-8" /> ...
```

`200` 表示请求成功，返回的是一段 HTML（首页内容）。

### 8.2 一个真实的 POST 请求（登录）

```python
import requests

r = requests.post(
    'http://shop-xo.hctestedu.com',
    params={'s': '/api/user/login', 'application': 'app', 'application_client_type': 'weixin'},
    data={'accounts': 'youer', 'pwd': '123456', 'type': 'username'},
)
print('状态码:', r.status_code)
print('返回  :', r.json()['msg'], '/ code =', r.json()['code'])
```

实测输出：

```text
状态码: 200
返回  : 登录成功 / code = 0
```

这个接口把 `s`（具体接口路径）放在 `params` 里，把账号密码放在 `data` 里，是商城项目一贯的写法，后面第 03、04 课会一直用到。

## 9. 常见报错和排查方法

### 9.1 `ModuleNotFoundError: No module named 'requests'`

没装库，或者装到了别的 Python 环境。

排查：

```powershell
pip install requests
pip list
```

如果 pip 里能看到，但 PyCharm 里还报错，检查右下角的解释器是不是同一个虚拟环境。

### 9.2 状态码不是 200

常见的有：

```text
400 参数错误   -> 参数名写错、格式不对（比如该用 json 却用了 data）
401 未登录     -> 缺少 token
404 地址错误   -> URL 或 s 参数写错
500 服务端错误 -> 接口本身出问题，不一定是你的代码问题
```

### 9.3 接口返回“参数错误”，但参数看着没错

先看请求方式对不对（GET 写成 POST 了？），再看参数放的位置对不对（`params` 还是 `data`）。

最直接的排查方法是拿接口文档里的 Content-Type 来对：

```text
application/json                  -> 用 json=
application/x-www-form-urlencoded -> 用 data=
```

### 9.4 返回的中文是乱码

有时候接口没声明编码，`r.text` 会乱码。可以手动指定：

```python
r.encoding = 'utf-8'
print(r.text)
```

### 9.5 `SSLError` 或连不上

多半是网络问题或者开了代理。先确认这个地址用浏览器能不能打开。
