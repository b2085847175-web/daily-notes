# 第03课 课堂笔记｜接口自动化接口流程实战（8月26日）

> 本节目标：用“登录 → 加购物车 → 查看购物车 → 查看地址 → 提交订单”五个接口串起一条完整业务流程；并把写重复了的 requests 代码封装成一个类，让调用变得简单。

---

## 0. 先用一句话理解本节

前两节学会了：发一个请求、保持会话、提取数据。

但真实业务不是发一个请求就完事，而是一条链：

```text
登录 -> 加入购物车 -> 查看购物车 -> 查看地址 -> 提交订单
```

每一步都要用到上一步的数据：

```text
登录    -> 拿到 token
加购物车 -> 要用 token
查购物车 -> 要用 token，还要拿到 goods_id
查地址   -> 要用 token，还要拿到 address
提交订单 -> 要用 token + goods_id + address
```

这就是**接口关联**：上一个接口的结果，是下一个接口的输入。

同时会暴露另一个问题：五个接口就要写五遍 `requests.post(...)`，每遍都要传一堆参数、都要写 `try/except`，重复代码太多。所以本节还要做**二次封装**：把重复的部分收进一个类里。

一句话总结：

```text
接口关联：把五个接口用数据串成一条链
二次封装：把重复的请求代码收进一个类，调用变简单
```

## 1. 新手先认识 6 个词

### 1.1 接口关联

上一个接口的返回结果里，有下一个接口需要的数据。

第 02 课讲的是“怎么把值取出来”，本节讲的是“取出来之后怎么用起来”。

### 1.2 二次封装

把已经写好的东西（这里是 `requests.post` / `requests.get`）**再包一层**，让调用更简单、改动更集中。

```text
不封装：每个接口都写一遍 requests.post(url, data=..., headers=...)
封装后：每个接口都写 关键词.发送请求POST(请求地址=..., 请求数据=...)
```

### 1.3 `**kwargs`

Python 的语法，意思是“**接收任意多个关键字参数**”，收到的是一个字典。

```python
def f(**kwargs):
    print(kwargs)

f(a=1, b=2)     # 打印 {'a': 1, 'b': 2}
```

有了它，封装的方法就不用提前规定死有几个参数。

### 1.4 字典解包 `**字典名`

和上面长得像，但用在**调用函数**的时候：

```python
func(**{'url': 'xxx', 'json': {'a': 1}})
# 等于
func(url='xxx', json={'a': 1})
```

前提是字典的键必须是字符串，而且要和函数的参数名对得上。

### 1.5 鸭子类型

Python 的一句俗话：“**如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。**”

意思是：不看你是什么类型，只看你有没有我需要的方法。

本节里 `requests` 模块有 `.request()`，`requests.session()` 对象也有 `.request()`，所以两个都能传进同一个方法。

### 1.6 断言（assert）

```python
assert 条件, '不满足时打印这句话'
```

条件成立就继续往下跑，不成立就直接报错。本节用它来检查每个接口是不是真的成功了。

## 2. 整体执行流程

```text
1. 登录接口        -> 取出 token
2. 加入购物车接口  -> 把 token 拼进 URL
3. 查看购物车接口  -> 取出 goods_id
4. 查看地址接口    -> 取出 address
5. 提交订单接口    -> 把 token + goods_id + address 一起用上
```

每一步都做两件事：

```text
把上一步的值拼进这一次请求
断言这一次的返回是不是预期
```

封装之后，流程没变，只是“发请求”这一步从 `requests.post(...)` 变成了 `client.send_post(...)`。

## 3. 接口关联.py：把五个接口串起来

文件位置：

```text
接口关联.py
```

### 3.1 第一步：登录，取出 token

```python
import jsonpath
import requests

login_url = 'http://shop-xo.hctestedu.com/index.php?s=/api/user/login&application=app&application_client_type=weixin'
login_data = {
    "accounts": "youtian",
    "pwd": "123456",
    "type": "username"
}
try:
    requ = requests.post(login_url, data=login_data)
    login_token = jsonpath.jsonpath(requ.json(), '$..token')[0]
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == '登录成功', '登陆失败'
except Exception as e:
    raise
```

这里有几个点值得注意：

```text
接口地址带了 ?s=/api/user/login   -> 商城的接口路径都写在 s 参数里
data=login_data                 -> 账号密码是表单格式提交
$..token 后面加了 [0]            -> 因为 jsonpath 返回的是列表
assert ... == '登录成功'         -> 接口返回成功 ≠ 业务成功，要看 msg
```

**重点**：接口返回 HTTP 200，不代表业务成功。必须看返回内容里的 `msg`（或 `code`）。这就是为什么要断言。

### 3.2 第二步：带着 token 加购物车

```python
shop_url = f'http://shop-xo.hctestedu.com/index.php?s=/api/cart/save&application=app&application_client_type=weixin&token={login_token}'
shop_data = {
    "goods_id": "2",
    "stock": "3"
}
try:
    requ = requests.post(shop_url, data=shop_data)
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == '加入成功', '加入失败'
except Exception as e:
    raise
```

关键在 `f'...token={login_token}'`：**把上一步取出来的 token 拼进 URL**。

`f'...'` 是 f-string，字符串前面加个 `f`，里面的 `{变量名}` 会被替换成变量的值。

### 3.3 第三步：查看购物车，取出 goods_id

```python
select_shop_url = f'http://shop-xo.hctestedu.com/index.php?s=/api/cart/index&application=app&application_client_type=weixin&token={login_token}'
try:
    requ = requests.post(select_shop_url)
    goods_id = jsonpath.jsonpath(requ.json(), '$..goods_id')[0]
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == 'success', '查看购物车失败'
except Exception as e:
    raise
```

这一步开始体现“关联”的价值：**加购物车时用的 goods_id 是我们自己传的，但查购物车时返回的 goods_id 是服务端真实记录的**，后面提交订单要用真实的那个。

### 3.4 第四步：查看地址，取出 address

```python
select_address_url = f'http://shop-xo.hctestedu.com/index.php?s=/api/useraddress/index&application=app&application_client_type=weixin&token={login_token}'
try:
    requ = requests.post(select_address_url)
    address = jsonpath.jsonpath(requ.json(), '$..address')[0]
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == 'success', '查看地址失败'
except Exception as e:
    raise
```

同样是“先用 token 查，再把返回值提取出来”。

### 3.5 第五步：提交订单，把前面的数据都用上

```python
add_url = f'http://shop-xo.hctestedu.com/index.php?s=/api/buy/add/index&application=app&application_client_type=weixin&token={login_token}'
data = {
    "buy_type": "goods",
    "goods_id": goods_id,
    "stock": "2",
    "spec": [],
    "address_id": address,
    "payment_id": "3",
    "site_model": 0,
    "user_note": ""
}

try:
    requ = requests.post(add_url, json=data)
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == '提交成功', '提交订单失败'
except Exception as e:
    raise
print(requ.json())
```

到这一步，`login_token`、`goods_id`、`address` 三个值全部用上了。

### 3.6 一条链看下来

| 步骤 | 用到上一步的什么 | 自己产出了什么 |
|---|---|---|
| 登录 | 无 | `login_token` |
| 加入购物车 | `login_token` | 无 |
| 查看购物车 | `login_token` | `goods_id` |
| 查看地址 | `login_token` | `address` |
| 提交订单 | `login_token`、`goods_id`、`address` | 订单结果 |

## 4. 为什么要二次封装 requests

### 4.1 不封装的问题

课上原话：

> 每个接口都要写 requests.post/get，url、json/data、headers、params 参数各不相同，还要写异常处理，重复代码太多。

看一看就明白了，五个接口里每个都长这样：

```python
try:
    requ = requests.post(url, data=..., headers=..., params=...)
    ...断言...
except Exception as e:
    raise
```

重复的部分：

```text
try/except 每次都要写
到底用 data 还是 json 每次都要判断
参数名各不相同，容易写错
```

### 4.2 封装的好处

```text
一处修改，处处生效
调用更简单
```

比如以后要给所有请求统一加超时时间，只改封装里的那一处就行，不用改五个地方。

## 5. api_client.py：封装到底怎么写的

文件位置：

```text
二次封装-工作版/api_client.py
```

完整代码：

```python
import requests


class ApiClient:
    """HTTP 请求客户端封装"""

    def __init__(self, session):
        self.session = session

    def send_post(self, **kwargs):
        url = kwargs.get("url", None)
        data = kwargs.get("data", None)
        params = kwargs.get("params", None)
        headers = kwargs.get("headers", None)
        files = kwargs.get("files", [])
        data_type = kwargs.get("data_type", "data").lower()

        request_data = {
            "url": url,
            "params": params,
            "headers": headers,
            "files": files,
        }
        if data_type == "json":
            request_data["json"] = data
        elif data_type == "data":
            request_data["data"] = data
        else:
            raise Exception("请求类型错误，仅支持json/data")

        try:
            response = self.session.request("post", **request_data)
            return response
        except Exception as e:
            print("post发送请求失败")
            raise
```

下面把几个新手不太熟的写法补上。

### 5.1 `def send_post(self, **kwargs)`

`**kwargs` 表示“把调用时传进来的所有关键字参数，收集成一个字典”。

调用方写：

```python
client.send_post(url='xxx', data={'a': 1})
```

方法内部就得到：

```python
kwargs == {'url': 'xxx', 'data': {'a': 1}}
```

好处是**参数不写死**：今天传两个，明天传五个，方法都不用改。

### 5.2 `kwargs.get("url", None)`

从字典里取值，取不到就给默认值。

```python
kwargs.get("url", None)      # 有 url 就返回它的值，没有就返回 None
kwargs.get("files", [])      # 没有 files 就返回空列表
```

这和直接写 `kwargs["url"]` 的区别是：**直接取没有的键会报 KeyError，用 get 不会**。

### 5.3 `data_type = kwargs.get("data_type", "data").lower()`

这一行做了两件事：

```text
1. 取出 data_type，没写就默认 'data'
2. 用 .lower() 转成小写
```

为什么要转小写？因为调用方可能写 `'JSON'`、`'Json'`、`'json'`，转成小写之后统一都是 `json`，就不会因为大小写不一致而判断错误。

### 5.4 自动区分 json / data

```python
if data_type == "json":
    request_data["json"] = data
elif data_type == "data":
    request_data["data"] = data
else:
    raise Exception("请求类型错误，仅支持json/data")
```

这就是“**按请求类型自动切换**”：

```text
传 data_type='json' -> 用 json= 发（JSON 格式）
传 data_type='data' -> 用 data= 发（表单格式，默认）
写别的            -> 直接报错，早发现
```

### 5.5 字典解包：`**request_data`

```python
response = self.session.request("post", **request_data)
```

刚才构造的字典是：

```python
request_data = {'url': 'xxx', 'params': {...}, 'headers': None, 'files': [], 'data': {...}}
```

`**request_data` 会把它展开成一个个参数：

```python
self.session.request("post", url='xxx', params={...}, headers=None, files=[], data={...})
```

**这就是“字典里没有就不放”的思路**：字典里只放这次请求真正用到的参数（`json` 和 `data` 只会有一个），展开时字典里有哪个键就传哪个参数。

好处很实在：同一个方法，有的请求传 json、有的传 data、有的带 headers，各自构造自己的字典就行，不用写一堆 `if` 判断。

### 5.6 `try/except` 包在里面

```python
try:
    response = self.session.request("post", **request_data)
    return response
except Exception as e:
    print("post发送请求失败")
    raise
```

异常处理被收进了封装里，**调用方就不用每次都写 try/except 了**。

注意最后那个 `raise`：它表示“打印完错误信息之后，把异常继续抛出去”。如果只 print 不 raise，错误就被吞掉了，测试会“假装成功”，这是很危险的写法。

### 5.7 `send_get` 和 `send_post` 的区别

```python
    def send_get(self, **kwargs):
        url = kwargs.get("url", None)
        params = kwargs.get("params", None)
        headers = kwargs.get("headers", None)
        files = kwargs.get("files", [])
        request_data = {
            "url": url,
            "params": params,
            "headers": headers,
            "files": files,
        }
        try:
            response = self.session.request("get", **request_data)
            return response
        except Exception as e:
            print("get发送请求失败")
            raise
```

区别只有两点：

```text
GET 不需要请求体，所以没有 data / json / data_type
最后调用的方式是 'get'
```

## 6. test_api_flow.py：封装之后怎么用

文件位置：

```text
二次封装-工作版/test_api_flow.py
```

### 6.1 第一步：创建客户端对象

```python
import jsonpath
import requests

from api_client import ApiClient

client = ApiClient(requests)
```

这句话的意思是：**创建一个客户端，把 `requests` 交给它使用**。

想让它保持会话，就换成：

```python
client = ApiClient(requests.session())
```

整个文件只有这一行需要改，这就是封装的价值。

### 6.2 调用变简单了

对比一下同一个请求的两种写法：

```python
# 不封装
try:
    requ = requests.post(login_url, data=login_data)
    assert jsonpath.jsonpath(requ.json(), '$..msg')[0] == '登录成功', '登录失败'
except Exception as e:
    raise

# 封装后
login_response = client.send_post(url=login_url, data=login_data)
assert jsonpath.jsonpath(login_response.json(), '$..msg')[0] == '登录成功', '登录失败'
```

差别：

```text
try/except 不用写了
参数用关键字传，一眼看得出传的是什么
```

### 6.3 五个接口的调用方式

```python
# 1. 登录
login_response = client.send_post(url=login_url, data=login_data)
login_token = jsonpath.jsonpath(login_response.json(), '$..token')[0]

# 2. 加入购物车（这次用 json 格式发）
cart_response = client.send_post(url=cart_url, data=cart_data, data_type='json')

# 3. 查看购物车
cart_index_response = client.send_get(url=cart_index_url)
goods_id = jsonpath.jsonpath(cart_index_response.json(), '$..goods_id')[0]

# 4. 查看地址
address_response = client.send_post(url=address_url)
address = jsonpath.jsonpath(address_response.json(), '$..address')[0]

# 5. 提交订单
order_response = client.send_post(url=order_url, data=order_data, data_type='json')
```

注意第 3 步用的是 `send_get`，因为查看购物车这个接口用的是 GET。

### 6.4 一个小细节

两个文件对“加入购物车”的发法不太一样：

```text
接口关联.py      ：用 data 发（表单格式）
test_api_flow.py ：用 data_type='json' 发（JSON 格式）
```

我把两种都跑了一遍，服务端都能返回“加入成功”：

```text
用 data 发加购 : 加入成功
用 json 发加购 : 加入成功
```

说明这个接口两种格式都支持。但**实际工作中要以接口文档为准**，不能靠“试出来能用”就一直用。

## 7. 鸭子类型：为什么能传 requests 也能传 session

### 7.1 创建对象时传的参数去哪了

```python
client = ApiClient(requests)
```

括号里传的东西，会自动赋值给 `__init__` 的参数：

```python
def __init__(self, session):
    self.session = session
```

所以 `self.session` 就是 `requests` 模块本身。

### 7.2 Python 是动态类型

参数不限定类型，传什么都能接住。传模块可以，传对象也可以。

### 7.3 为什么两个都能用

因为 `__init__` 里存下来的东西，后面只用到了它的 `.request()` 方法：

```python
response = self.session.request("post", **request_data)
```

而：

```text
requests 模块    有 .request()   -> 能用
requests.session() 对象 也有 .request()  -> 也能用
```

调用方式一样，能用就行，Python 不管你到底是个模块还是个对象。这就是**鸭子类型**。

### 7.4 两者的实际区别

| 传什么 | 行为 |
|---|---|
| `ApiClient(requests)` | 每次请求独立，相当于每次新开浏览器 |
| `ApiClient(requests.session())` | 自动保持 cookie、关联登录状态 |

所以第 14 课讲 Session 复用的时候，只需要把这一行改掉，整个框架的会话行为就变了。

## 9. 常见报错和排查方法

### 9.1 `IndexError: list index out of range`

写 `jsonpath.jsonpath(...)[0]` 时报这个错，说明 **jsonpath 一个都没匹配到**，列表是空的，取 `[0]` 自然失败。

最常见的原因是**上一步的接口其实失败了**。比如登录失败，返回里根本没有 token，再去取 `$..token` 就是空的。

排查：先把返回打印出来看。

```python
print(requ.json())
```

### 9.2 `AssertionError: 登录失败`

断言没通过，说明接口返回的 `msg` 不是“登录成功”。

可能原因：

```text
账号密码错了
接口地址写错了（s 参数）
参数格式不对（该 data 用了 json）
```

### 9.3 `AssertionError: 加入失败`

多半是 token 没传对。检查：

```text
token 有没有真的取出来（打印看一眼）
token 有没有拼进 URL（f-string 里的 {login_token}）
token 是不是同一个账号的
```

### 9.4 `MissingSchema: Invalid URL 'None'`

这是一个**很隐蔽、但很典型**的错。我实测过：

```python
client.send_post(urls='http://shop-xo.hctestedu.com/index.php')
```

输出：

```text
post发送请求失败
MissingSchema : Invalid URL 'None': No scheme supplied. Perhaps you meant https://None?
```

原因：参数名写成了 `urls`，但封装里读的是 `kwargs.get("url")`，读不到就是 `None`，最后发了一个地址为 `None` 的请求。

**为什么说它隐蔽**？因为封装用的是 `**kwargs` + `.get()`，参数名写错**不会当场报错**，会一路默默传到发请求那一步才炸。所以看到 `Invalid URL 'None'`，第一反应就是去检查参数名拼写。

### 9.5 `Exception: 请求类型错误，仅支持json/data`

`data_type` 写错了。实测：

```python
client.send_post(url=..., data={'a': 1}, data_type='jsons')
```

输出：

```text
Exception : 请求类型错误，仅支持json/data
```

注意大小写不用担心，封装里做了 `.lower()`：

```python
client.send_post(url=..., data_type='JSON')   # 实测正常，返回 200
```

### 9.6 `ModuleNotFoundError: No module named 'api_client'`

运行目录不对。`test_api_flow.py` 里写的是：

```python
from api_client import ApiClient
```

两个文件必须在一起，所以要先进到 `二次封装-工作版` 目录再运行。

### 9.7 断言没用，跑完还是显示成功

检查是不是忘了写 `assert`，只 `print` 了结果。**打印不等于检查**，接口返回“登录失败”时 pytest 依然是 PASSED。这一点第 09 课会专门讲。

## 10. 本节重点记忆

| 名称 | 作用 |
|---|---|
| 接口关联 | 上一个接口的结果，是下一个接口的输入 |
| `f'...{token}'` | 把变量的值拼进字符串（URL 里最常用） |
| 二次封装 | 把重复的请求代码收进一个类 |
| `**kwargs` | 接收任意多个关键字参数，得到字典 |
| `kwargs.get(key, 默认值)` | 安全取值，取不到用默认值 |
| `data_type = ....lower()` | 转小写，容错大小写 |
| `request_data["json"] / ["data"]` | 按类型自动选择传参方式 |
| `**request_data` | 字典解包，展开成一个个参数 |
| `try/except ... raise` | 封装异常，但要把错误继续抛出去 |
| `self.session.request('post', ...)` | 真正发请求的地方 |
| 鸭子类型 | 有 `.request()` 就能用，所以 requests 和 session 都能传 |
| `assert` | 检查业务结果，不是只看 HTTP 200 |

两句话总结：

> 接口关联：取上一步的值，拼进下一步的请求。
>
> 二次封装：把 try/except、参数判断这些重复劳动收进类里，调用处只留“传参 + 断言”。
