# 第05课 课堂笔记｜接口自动化框架核心执行器优化（8月28日）

> 本节目标：让框架从“能跑”变成“好用”。装上 Allure 出漂亮的测试报告，把用例标题和模块显示出来，用进度条看到执行过程，并且让关键字可以放在外面动态加载，别人扩展不用改核心代码。

## 0. 先用一句话理解本节

上一节的框架能跑通用例了，但有个问题：**跑完只有一行 `1 passed`，看不出什么名堂**。

```text
不知道哪条用例在跑
不知道跑到哪一步了
失败的时候不知道是哪一步失败
```

本节就是来解决这些的，做四件事：

```text
1. 装 Allure，生成网页版测试报告
2. 把 YAML 里的用例标题、一级模块、二级模块显示到报告里
3. 用 tqdm 在终端显示进度条
4. 关键字支持从外部目录动态加载，不用改执行器代码
```

一句话总结：

```text
从“能跑通”升级到“看得清、好扩展”
```

## 1. 新手先认识 6 个词

### 1.1 Allure

一个测试报告工具。它把执行结果渲染成一个网页：有几条用例、哪条通过哪条失败、每步花了多久，一目了然。

### 1.2 allure-pytest

Allure 的 **pytest 插件**（Python 包），负责在执行过程中把结果写成 JSON 数据。

### 1.3 allure-commandline

Allure 的**命令行工具**（Java 程序），负责把上一步生成的 JSON 数据渲染成 HTML 报告。

**这两个是两回事，都要装**：一个生成数据，一个生成报告。

### 1.4 allure-results 和 allure-report

```text
allure-results  -> 原始数据（一堆 JSON），程序看的
allure-report   -> 最终报告（HTML 网页），人看的
```

### 1.5 tqdm

在终端显示进度条的库。用例步骤多的时候，能直观看到跑到哪了。

### 1.6 动态加载关键字

`操作类型` 在默认的 `Keywords` 类里找不到时，去 `HAT/key_dir` 目录里按文件名找同名模块加载。这样别人加新关键字，不用动执行器。

## 2. 整体执行流程

```text
1. pytest 执行用例，同时把结果写进 allure-results
2. allure generate 读 allure-results，生成 allure-report
3. allure_combine 把报告合并成 complete.html，双击就能看
```

对应到 `main.py`：

```text
pytest.main(pytest_ars)                        -> 跑用例 + 产出原始数据
os.system('allure generate -c -o allure-report') -> 生成 HTML 报告
combine_allure('./allure-report')                -> 合并成一个文件
```

一条用例执行时的顺序：

```text
读基础配置 -> 设置报告标题/模块
  -> 进入步骤循环 -> 每步更新进度条
    -> 进入 allure 步骤 -> 找关键字方法 -> 发请求
```

## 4. main.py：一条命令跑用例 + 出报告

文件位置：

```text
main.py
```

完整代码：

```python
import os

import pytest
from allure_combine import combine_allure

pytest_ars = [
    '-v',
    '-s',
    '--capture=sys',
    '--clean-alluredir',
    '--alluredir=allure-results',
    './HAT/core/testrun.py'
]

pytest.main(pytest_ars)

os.system('allure generate -c -o allure-report')

combine_allure('./allure-report')
```

以后运行整个框架，只要一条命令：

```powershell
python main.py
```

### 4.1 pytest 的参数逐个解释

| 参数 | 作用 |
|---|---|
| `-v` | 详细模式，终端显示每条用例的名称和结果 |
| `-s` | 显示代码里的 `print` 输出，相当于 `--capture=no` |
| `--capture=sys` | 指定用 sys 层捕获输出 |
| `--clean-alluredir` | 运行前清空旧的 `allure-results`，避免历史数据混进报告 |
| `--alluredir=allure-results` | 指定 Allure 原始结果的保存目录 |
| `./HAT/core/testrun.py` | 指定要执行的测试文件 |

**注意 `-s` 和 `--capture=sys` 的关系**：两个都写的时候，后面的捕获参数可能会把 `-s` 覆盖掉。所以不是写了 `-s` 就一定能看到 print，要看最终是谁生效。

### 4.2 allure generate 的参数

```powershell
allure generate -c -o allure-report
```

| 参数 | 作用 |
|---|---|
| `allure generate` | 读 `allure-results` 里的原始结果，生成 HTML 报告 |
| `-c` | 等于 `--clean`，报告目录已存在时先清空再生成 |
| `-o allure-report` | 指定输出目录 |

### 4.3 另外两个常用命令

```powershell
allure open allure-report      # 打开已经生成的 HTML 报告
allure serve allure-results    # 读原始数据，起一个临时服务直接预览
```

三个命令的区别：

```text
generate -> 生成报告文件，可以发给别人
open     -> 打开已经生成好的报告
serve    -> 临时预览，不生成报告文件
```

**记住一点**：`allure-results` 是原始数据，`allure-report` 是最终报告。正式执行时一般先清空再重新生成，否则可能看到旧数据。

## 5. 报告优化：让报告看得懂

光有报告还不够，还要让报告里的内容有意义。本节做了三件事。

### 5.1 合并报告：解决双击打不开的问题

**问题**：`allure-report` 目录里直接双击 `index.html`，有些电脑会因为浏览器的安全限制看不到数据（页面一片空白）。

**解决**：用 `allure_combine` 把报告合并成一个 `complete.html`，不需要额外参数，双击就能看。

安装：

```powershell
pip install allure_combine==1.0.11 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

代码：

```python
from allure_combine import combine_allure

combine_allure('./allure-report')
```

运行完会生成：

```text
allure-report/complete.html
```

### 5.2 标题和模块：从 YAML 里读

先在 YAML 的“基础配置”里写好这些信息：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录接口
  一级模块: 登录模块
  二级模块: 用户登录
  优先级: P0
```

执行器里读出来，写进报告：

```python
import allure

base_info = data_yaml.get('基础配置', {})

allure.dynamic.parameter('caseinfo', '')
allure.dynamic.feature(base_info.get('一级模块', '默认模块'))
allure.dynamic.story(base_info.get('二级模块', '默认模块'))
allure.dynamic.title(base_info.get('用例标题', '默认用例标题'))
```

三个方法对应报告里的三个位置：

| 方法 | 对应 YAML 的字段 | 报告里显示成 |
|---|---|---|
| `allure.dynamic.title` | `用例标题` | 用例的名称 |
| `allure.dynamic.feature` | `一级模块` | 大分类 |
| `allure.dynamic.story` | `二级模块` | 小分类 |

注意每个 `.get()` 都写了默认值，比如 `'默认模块'`。这样 YAML 里没写这些字段时也不会报错，只是显示默认名字。

### 5.3 步骤：用 @allure.step 把过程展示出来

**第一层**：在请求方法上加装饰器。

```python
import allure


class Keywords:
    @allure.step("发送请求POST")
    def 发送请求POST(self, **kwargs):
        ...

    @allure.step("发送请求GET")
    def 发送请求GET(self, **kwargs):
        ...
```

**第二层**：执行器里给每个 YAML 步骤再包一层。

```python
with allure.step(step_name):
    response = key_func(**step_value)
```

`with allure.step(...)` 是“上下文管理器”的写法：`with` 里面的代码都算作这一步的内容。

两层加起来，报告里会显示成嵌套的样子：

```text
发送登录请求          <- YAML 里的步骤名
    发送请求POST      <- 请求方法上的装饰器
```

一眼就能看出“哪一步、发的是什么请求”。

## 6. 执行优化：tqdm 进度条

### 6.1 安装

```powershell
pip install tqdm==4.67.3 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 6.2 代码

```python
from tqdm import tqdm

with tqdm(total=len(steps), desc='开始执行') as pbar:
    for step in steps:
        step_name, step_value = next(iter(step.items()))
        pbar.set_description(f'当前步骤:{step_name}')
        pbar.update(1)

        with allure.step(step_name):
            response = key_func(**step_value)
```

### 6.3 三个参数

| 参数 | 作用 |
|---|---|
| `total` | 一共多少个步骤，决定了进度条的总长度 |
| `desc` | 进度条前面显示的说明文字 |
| `update(1)` | 每执行完一步，进度加 1 |

`set_description` 可以在执行过程中**动态改说明文字**。本节执行器里写的是：

```python
pbar.set_description(f'{base_info.get("用例标题", "默认用例标题")}-当前步骤:{step_name}')
```

所以进度条上会显示成：

```text
商城登录接口-当前步骤:发送登录请求: 100%|██████████| 1/1 [00:00<00:00,  8.33it/s]
```

**好处**：用例步骤多、跑得久的时候，一眼就知道现在跑到哪条用例的哪一步了，卡住了也能马上发现。

## 7. 动态关键字：key_dir

### 7.1 要解决什么问题

现在的关键字都写在 `HAT/keywords/api_client.py` 的 `Keywords` 类里。如果同事想加一个新接口类型，就得改这个核心文件。

**目标**：让关键字可以放在外面，加新关键字不用动核心执行器。

### 7.2 命名规则

```text
文件名 = 操作类型
类名   = 操作类型
方法名 = 操作类型
```

三个必须**一模一样**。比如 `HAT/key_dir/发送请求POST.py`：

```python
import allure


class 发送请求POST:
    """动态关键字示例：文件名、类名、方法名都必须和操作类型一致"""

    def __init__(self, request):
        self.request = request

    @allure.step("发送请求POST")
    def 发送请求POST(self, **kwargs):
        request_data = {
            "url": kwargs.get("请求地址", None),
            "params": kwargs.get("URL参数", None),
            "headers": kwargs.get("请求头", None),
            "files": kwargs.get("文件列表", []),
        }

        data = kwargs.get("请求数据", None)
        data_type = kwargs.get("请求类型", "data").lower()

        if data_type == "json":
            request_data["json"] = data
        elif data_type == "data":
            request_data["data"] = data
        else:
            raise Exception("请求类型错误，仅支持json/data")

        response = self.request.request("post", **request_data)
        return response
```

### 7.3 执行器里的加载逻辑

```python
try:
    key_func = client.__getattribute__(key)
except AttributeError:
    if str(KEY_DIR) not in sys.path:
        sys.path.append(str(KEY_DIR))

    try:
        module = __import__(key)
        class_ = getattr(module, key)
        key_func = class_(requests).__getattribute__(key)
    except (ImportError, AttributeError) as e:
        raise AssertionError(f'{step_name} 没有找到关键字方法：{key}') from e
```

逻辑是两段：

```text
先在 Keywords 类里找 -> 找到就直接用
找不到（AttributeError）-> 去 key_dir 目录里找同名文件
```

### 7.4 KEY_DIR 是怎么算出来的

```python
from pathlib import Path

KEY_DIR = Path(__file__).resolve().parents[1] / 'key_dir'
```

这行有点绕，我实际跑了一遍，把每一步的值打印出来：

```text
__file__   = ...\05-...\HAT\core\testrun.py
parents[0] = ...\05-...\HAT\core
parents[1] = ...\05-...\HAT
KEY_DIR    = ...\05-...\HAT\key_dir
```

解释：

```text
__file__     当前这个 py 文件的位置
.resolve()   转成绝对路径
.parents[0]  所在目录（core）
.parents[1]  上一级目录（HAT）
/ 'key_dir'  拼上 key_dir
```

**为什么不用 `./HAT/key_dir` 这种相对路径？** 因为相对路径依赖“你从哪个目录运行命令”，换台电脑或者从别的地方跑就找不到了。用 `__file__` 算出来的路径，永远相对于这个脚本自己，更稳。

### 7.5 动态加载实测

我把这个过程完整跑了一遍，确实能加载到并成功调用：

```text
动态加载到的方法: <bound method 发送请求POST.发送请求POST of <发送请求POST.发送请求POST object ...>>
实际调用结果    : 200
```

说明“按操作类型去 key_dir 找同名文件”这条路是通的。

### 7.6 小细节：别把路径重复加进去

```python
if str(KEY_DIR) not in sys.path:
    sys.path.append(str(KEY_DIR))
```

先判断再添加。因为每条用例、每个步骤都可能触发这段代码，无脑 append 会让 `sys.path` 里堆满重复路径。

## 9. 常见报错和排查方法

### 9.1 `'allure' 不是内部或外部命令`

命令行工具没配好。检查：

```text
allure-commandline 解压了吗？
解压目录里的 bin 路径加到环境变量 Path 了吗？
加完之后重启终端 / PyCharm 了吗？
```

配好后用 `allure --version` 验证。

### 9.2 `ModuleNotFoundError: No module named 'allure'`

装的是命令行工具，但没装 Python 插件。补上：

```powershell
pip install allure-pytest==2.13.5
```

### 9.3 报告打开是空白页

浏览器的安全限制导致 `index.html` 读不到同目录的数据。用合并后的报告：

```python
combine_allure('./allure-report')
```

然后双击 `allure-report/complete.html`。

### 9.4 报告里有上上次的旧数据

忘了清空。运行用例时加 `--clean-alluredir`，生成报告时加 `-c`：

```text
pytest ... --clean-alluredir --alluredir=allure-results
allure generate -c -o allure-report
```

### 9.5 报告里用例标题是“默认用例标题”

YAML 里的 `基础配置` 没写，或者字段名写错了。检查：

```yaml
基础配置:
  用例标题: 商城登录接口
  一级模块: 登录模块
  二级模块: 用户登录
```

代码里取的是 `用例标题`、`一级模块`、`二级模块` 这三个键名，要完全一致。

### 9.6 `AssertionError: xxx 没有找到关键字方法`

两处都找了但都没找到。检查：

```text
YAML 里的“操作类型”写的是什么？
Keywords 类里有没有同名方法？
key_dir 里有没有同名文件？类名、方法名是不是也一致？
```

三个名字（文件名、类名、方法名）必须和操作类型完全一样。

### 9.7 终端看不到 print 输出

`-s` 和 `--capture=sys` 同时写时可能互相影响。想稳定看到 print，可以只保留 `-s`，或者用 `--capture=no`。

## 10. 本节重点记忆

| 名称 | 作用 |
|---|---|
| `allure-pytest` | Python 插件，负责生成原始数据 |
| `allure-commandline` | 命令行工具，负责生成 HTML 报告 |
| `allure-results` | 原始 JSON 数据 |
| `allure-report` | 最终 HTML 报告 |
| `--alluredir` | 指定原始数据目录 |
| `--clean-alluredir` | 运行前清空原始数据 |
| `allure generate -c -o` | 生成报告 |
| `allure open` / `allure serve` | 打开 / 临时预览报告 |
| `combine_allure()` | 合并成 complete.html，双击可看 |
| `allure.dynamic.title/feature/story` | 从 YAML 设置标题和模块 |
| `@allure.step` | 把方法标记成报告里的一个步骤 |
| `with allure.step(name)` | 把代码块标记成报告里的一个步骤 |
| `tqdm(total=..., desc=...)` | 进度条 |
| `pbar.set_description()` / `pbar.update(1)` | 改描述 / 进度加一 |
| `KEY_DIR` | 动态关键字目录 |
| `Path(__file__).resolve().parents[1]` | 相对脚本自身算目录，比 `./` 稳 |
| 命名规则 | 文件名 = 类名 = 方法名 = 操作类型 |

两句话总结：

> 报告三件套：`allure-pytest` 出数据，`allure generate` 出报告，`combine_allure` 出能双击打开的单文件。
>

### 练习 5：加一个自己的动态关键字

在 `HAT/key_dir/` 下新建 `发送请求GET.py`：

```python
import allure


class 发送请求GET:
    def __init__(self, request):
        self.request = request

    @allure.step("发送请求GET")
    def 发送请求GET(self, **kwargs):
        response = self.request.request(
            "get",
            url=kwargs.get("请求地址", None),
            params=kwargs.get("URL参数", None),
            headers=kwargs.get("请求头", None),
        )
        return response
```

然后想办法验证它会被加载（提示：`Keywords` 里已经有 `发送请求GET`，所以它会走第一条路；想验证动态加载，可以先把 `Keywords` 里的同名方法注释掉再跑）。
