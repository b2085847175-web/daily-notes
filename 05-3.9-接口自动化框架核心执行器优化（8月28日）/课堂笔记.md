### 安装Allure测试报告

- 先安装 `allure-pytest` 插件，版本固定用 `2.13.5`
- `allure-commandline` 对应版本固定用 `2.18.1`

```bash
pip install allure-pytest==2.13.5 -i https://pypi.tuna.tsinghua.edu.cn/
```

如果镜像源找不到版本，使用官方源：

```bash
pip install allure-pytest==2.13.5 -i https://pypi.org/simple
```

- 再下载 `allure-commandline` 压缩包
- 解压后，把 `allure-commandline` 里面的 `bin` 目录路径，配置到环境变量 `Path` 中
- 配置完成后关机重启，或者至少重启 Pycharm / 终端

检查是否安装成功：

```bash
allure --version
```

- 注意：`allure-pytest` 是 Pytest 插件，版本要安装 `2.13.5`

### 使用Allure生成报告

教学代码里的运行方式：

```python
import os
import pytest

pytest_ars = [
    '-v',
    '-s',
    '--capture=sys',
    '--clean-alluredir',
    '--alluredir=allure-results',
    './HAT/core/TestRunner.py'
]

pytest.main(pytest_ars)

os.system('allure generate -c -o allure-report')
```

Pytest 参数含义：

- `-v`：详细模式，终端会显示每条用例的名称和执行结果
- `-s`：显示测试代码里的 `print` 输出，相当于 `--capture=no`
- `--capture=sys`：指定用 `sys` 层捕获输出；和 `-s` 同时写时，后面的捕获参数可能会覆盖 `-s`
- `--clean-alluredir`：运行前清空旧的 `allure-results`，避免历史用例数据混进报告
- `--alluredir=allure-results`：指定 Allure 原始结果保存目录，里面生成的是 JSON 数据
- `./HAT/core/TestRunner.py`：指定要执行的测试文件

`allure generate` 参数含义：

```bash
allure generate -c -o allure-report
```

- `allure generate`：读取 `allure-results` 里的原始结果，生成能打开的 HTML 报告
- `-c`：等价于 `--clean`，如果 `allure-report` 已存在，先清空再生成
- `-o allure-report`：指定最终 HTML 报告的输出目录

常用打开报告方式：

```bash
allure open allure-report
```

- `allure open`：打开本地已生成的 HTML 报告

也可以不先生成报告，直接临时预览：

```bash
allure serve allure-results
```

- `allure serve`：读取原始结果，启动临时服务并在浏览器打开报告

注意：`allure-results` 是原始测试数据，`allure-report` 是最终报告；一般正式执行时先清空，再重新生成。

### 报告优化：合并报告

`allure-report` 直接打开 `index.html` 时，有些电脑会因为浏览器安全限制看不到数据。`allure_combine` 可以把报告合并成一个 `complete.html`，不需要额外参数也能直接打开。

安装：

```bash
pip install allure_combine==1.0.11 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

镜像源失败时用：

```bash
pip install allure_combine==1.0.11 -i https://pypi.org/simple
```

`main.py` 对应代码：

```python
import os
import pytest
from allure_combine import combine_allure

pytest_ars = [
    '-v',
    '-s',
    '--capture=sys',
    '--clean-alluredir',
    '--alluredir=allure-results',
    './HAT/core/testrun.py'
]

pytest.main(pytest_ars)

os.system('allure generate -c -o allure-report')
combine_allure('./allure-report')
```

- `allure generate`：生成普通 HTML 报告
- `combine_allure('./allure-report')`：生成 `allure-report/complete.html`

### 报告优化：标题和模块

YAML 中增加基础配置：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录接口
  一级模块: 登录模块
  二级模块: 用户登录
  优先级: P0
```

测试执行器中读取这些配置，写入报告：

```python
import allure

base_info = data_yaml.get('基础配置', {})

allure.dynamic.parameter('caseinfo', '')
allure.dynamic.feature(base_info.get('一级模块', '默认模块'))
allure.dynamic.story(base_info.get('二级模块', '默认模块'))
allure.dynamic.title(base_info.get('用例标题', '默认用例标题'))
```

- `title`：报告里显示的用例标题
- `feature`：一级模块
- `story`：二级模块

### 报告优化：请求方法步骤

二次封装的方法上加 `@allure.step`：

```python
import allure

class Keywords:
    @allure.step("发送请求POST")
    def 发送请求POST(self, **kwargs):
        ...

    @allure.step("发送请求GET")
    def 发送请求GET(self, **kwargs):
        ...
```

执行器里再给每个 YAML 步骤加一层步骤：

```python
with allure.step(step_name):
    response = key_func(**step_value)
```

这样报告中会显示类似：

```text
发送登录请求
    发送请求POST
```

### 执行优化：进度条

安装：

```bash
pip install tqdm==4.67.3 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

对应代码：

```python
from tqdm import tqdm

with tqdm(total=len(steps), desc='开始执行') as pbar:
    for step in steps:
        step_name, step_value = next(iter(step.items()))
        pbar.set_description(f'当前步骤:{step_name}')
        pbar.update(1)

        with allure.step(step_name):
            response = key_func(**step_value)
```

- `total`：总步骤数
- `set_description`：修改进度条前面的描述
- `update(1)`：每执行完一个步骤，进度加 1

### 报告优化：动态关键字

当 `操作类型` 在默认 `Keywords` 类里找不到时，去 `HAT/key_dir` 目录动态加载。这样同事可以扩展关键字，不需要修改核心执行器。

命名规则：

```text
文件名 = 操作类型
类名 = 操作类型
方法名 = 操作类型
```

例如 `HAT/key_dir/发送请求POST.py`：

```python
import allure


class 发送请求POST:
    def __init__(self, request):
        self.request = request

    @allure.step("发送请求POST")
    def 发送请求POST(self, **kwargs):
        request_data = {
            "url": kwargs.get("请求地址", None),
            "params": kwargs.get("URL参数", None),
            "headers": kwargs.get("请求头", None),
            "files": kwargs.get("文件列表", []),
        }

        data = kwargs.get("请求数据", None)
        data_type = kwargs.get("请求类型", "data").lower()

        if data_type == "json":
            request_data["json"] = data
        elif data_type == "data":
            request_data["data"] = data
        else:
            raise Exception("请求类型错误，仅支持json/data")

        response = self.request.request("post", **request_data)
        return response
```

执行器里的加载逻辑：

```python
import sys

try:
    key_func = client.__getattribute__(key)
except AttributeError:
    sys.path.append(str(KEY_DIR))

    module = __import__(key)
    class_ = getattr(module, key)
    key_func = class_(requests).__getattribute__(key)
```

这里的 `key` 就是 YAML 里的 `操作类型`。
