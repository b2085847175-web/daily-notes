# 第06课 课堂笔记｜测试环境动态切换机制（8月29日）

> 本节目标：把“会变化的数据”从 YAML 用例里抽出来，放到 `context.yaml`。以后切换开发环境、测试环境、正式环境，只需要改配置，不用改每一条用例。

---

## 0. 先用一句话理解本节

上一节的登录用例里，请求地址是直接写死的：

```yaml
请求地址: http://shop-xo.hctestedu.com
```

如果明天换成测试环境，就要把 YAML 里的地址改掉。用例多了以后，每个文件都要改，很容易漏。

本节的做法是：

1. 把会变化的数据单独放到 `context.yaml`。
2. Python 启动时，先把这个文件读进内存。
3. YAML 用例里写占位符 `{{URL}}`。
4. 执行用例之前，把 `{{URL}}` 替换成真实地址。

也就是：

```text
会变化的数据 -> context.yaml
内存里的共享数据 -> g_context
YAML 里的占位符 -> {{变量名}}
把占位符替换成真实值 -> refresh 渲染
```

---

## 1. 新手先认识 4 个词

### 1.1 全局变量

全局变量可以理解成“整个项目都能拿到的一份数据”。

比如：

```text
URL = http://shop-xo.hctestedu.com
NAME = youyi
PWD = 123456
```

很多用例都要用 URL、账号、密码、数据库连接信息，这些数据适合做成全局变量。

### 1.2 context.yaml

`context.yaml` 是“环境配置文件”，专门存放会变化的数据。

本课的 `context.yaml` 内容很简单：

```yaml
URL: http://shop-xo.hctestedu.com
```

它相当于一张配置表：变量名是 `URL`，变量值是后面的网址。

### 1.3 模板和占位符

YAML 用例不直接写真实网址，而是写：

```yaml
请求地址: '{{URL}}'
```

这里的 `{{URL}}` 不是真实网址，而是一个“占位符”。你可以把它理解成填空题：

```text
请求地址：{{URL}}
```

等真正执行时，再把答案填进去。

### 1.4 渲染

“渲染”就是“把占位符替换成真实值”的过程。

```text
渲染前：'{{URL}}'
渲染后：'http://shop-xo.hctestedu.com'
```

本课用 Jinja2 这个库来完成渲染。

---

## 2. 整体执行流程

先看全局流程，不急着看代码细节：

```text
1. 读取 context.yaml
2. 把 {'URL': 'http://shop-xo.hctestedu.com'} 放进 g_context
3. 读取 login.yaml
4. 拿到用例步骤
5. 步骤里写着 请求地址: '{{URL}}'
6. 从 g_context 取出 {'URL': 'http://shop-xo.hctestedu.com'}
7. 用 refresh 把 {{URL}} 替换成真实地址
8. 替换后得到完整请求数据
9. 根据“操作类型”找到 Keywords 方法
10. 发送接口请求
```

对应到文件：

```text
context.yaml
  -> YamlCaseParser.load_context_from_yaml()
  -> g_context().set_by_dict()
  -> TestRunner 读取 login.yaml
  -> VarRender.refresh()
  -> Keywords.发送请求POST()
  -> requests 发送请求
```

## 3. g_context：全局变量容器

文件位置：

```text
HAT/core/globalContext.py
```

完整代码：

```python
class g_context:
    """全局变量容器，_dic 是类变量，用于多处共享数据"""

    _dic = {}

    def set_dict(self, key, value):
        self._dic[key] = value

    def set_by_dict(self, dic):
        self._dic.update(dic)

    def get_dict(self, key):
        return self._dic.get(key, None)

    def show_dict(self):
        return self._dic
```

### 3.1 `_dic = {}` 是什么

`_dic` 是一个字典，用来存全局变量。

```python
_dic = {}
```

它写在类里面，但不在 `__init__` 里面，所以它是“类变量”。

你可以这样理解：

- 每个 `g_context()` 对象是一个“人”。
- `_dic` 是墙上的一块“公共白板”。
- 无论谁来读、谁来写，看到的都是同一块白板。

所以下面两个对象拿到的是同一份数据：

```python
a = g_context()
b = g_context()

a.set_dict("URL", "http://shop-xo.hctestedu.com")

print(b.get_dict("URL"))
```

输出：

```text
http://shop-xo.hctestedu.com
```

虽然 `a` 和 `b` 是两个不同对象，但 `_dic` 属于类，不属于某一个对象，所以它们共享同一份数据。

### 3.2 四个方法分别做什么

#### `set_dict(key, value)`：设置一个变量

```python
g_context().set_dict("URL", "http://shop-xo.hctestedu.com")
```

相当于在白板上写：

```text
URL = http://shop-xo.hctestedu.com
```

内部执行的是：

```python
self._dic["URL"] = "http://shop-xo.hctestedu.com"
```

#### `set_by_dict(dic)`：批量设置变量

```python
g_context().set_by_dict({
    "URL": "http://shop-xo.hctestedu.com",
    "NAME": "youyi"
})
```

相当于一次写多个：

```text
URL = http://shop-xo.hctestedu.com
NAME = youyi
```

内部执行的是：

```python
self._dic.update(dic)
```

`update` 的意思是：把新字典里的键值对合并到原来的字典里。

#### `get_dict(key)`：读取一个变量

```python
url = g_context().get_dict("URL")
```

如果 `URL` 存在，就返回对应值；如果不存在，就返回 `None`。

```python
print(g_context().get_dict("NOT_EXIST"))
```

输出：

```text
None
```

#### `show_dict()`：读取全部变量

```python
print(g_context().show_dict())
```

输出类似：

```text
{'URL': 'http://shop-xo.hctestedu.com'}
```

注意：`show_dict()` 返回的是原来的字典，不是复制出来的新字典。后面的课程会用到 `copy.deepcopy`，就是为了避免不小心改到全局数据。

## 4. context.yaml 怎么被读进来

文件位置：

```text
examples/api-cases-yaml/context.yaml
```

本课内容：

```yaml
URL: http://shop-xo.hctestedu.com
```

读取函数在：

```text
HAT/parse/YamlCaseParser.py
```

代码如下：

```python
import os.path
import yaml

from HAT.core.globalContext import g_context


def load_context_from_yaml(file_path):
    yaml_file_path = os.path.join(file_path, "context.yaml")

    with open(yaml_file_path, "r", encoding="utf-8") as file:
        data = yaml.load(file, Loader=yaml.FullLoader)

        if data:
            g_context().set_by_dict(data)

        print("全局变量", g_context().show_dict())
```

### 4.1 逐行解释

```python

```

把文件夹路径和文件名拼起来。

如果 `file_path` 是：

```text
examples/api-cases-yaml
```

那么 `yaml_file_path` 就是：

```text
examples/api-cases-yaml/context.yaml
```

```python
with open(yaml_file_path, "r", encoding="utf-8") as file:
```

打开文件，`encoding="utf-8"` 是为了正确读取中文。

```python
data = yaml.load(file, Loader=yaml.FullLoader)
```

把 YAML 文本变成 Python 字典。

原来的 YAML：

```yaml
URL: http://shop-xo.hctestedu.com
```

变成：

```python
{"URL": "http://shop-xo.hctestedu.com"}
```

```python
if data:
    g_context().set_by_dict(data)
```

如果 YAML 里确实有数据，就把这些数据批量放进全局变量。

```python
print("全局变量", g_context().show_dict())
```

打印出来方便观察，运行时你会看到：

```text
全局变量 {'URL': 'http://shop-xo.hctestedu.com'}
```

### 4.2 什么时候加载 context.yaml

在 `HAT/core/TestRunner.py` 开头有这样两行：

```python
load_context_from_yaml('examples/api-cases-yaml')

```

这两行写在类的外面，所以 Python 一加载这个测试文件，就会先执行：

1. 读取 `context.yaml`
2. 把 URL 放进 `g_context`
3. 读取 `login.yaml`
4. 把登录用例数据放进 `data`

也就是说，用例还没开始跑，环境数据就已经准备好了。

## 5. YAML 用例里怎么用变量

`login.yaml` 的关键部分：

```yaml
基础配置:
  用例类型: ApiCase
  用例标题: 商城登录用例标题
  一级模块: 登录模块
  二级模块: 登录功能

用例步骤:
  - 发送登陆接口:
      操作类型: 发送请求POST
      请求地址: '{{URL}}'
      URL参数:
        s: /api/user/login
        application: app
        application_client_type: weixin
      请求头:
        Content-Type: application/x-www-form-urlencoded
      请求数据:
        accounts: youyi
        pwd: "123456"
        type: username
```

重点是这一行：

```yaml
请求地址: '{{URL}}'
```

### 5.1 为什么要加单引号

在 YAML 里，`{` 是特殊符号，表示字典开始。如果写成：

```yaml
请求地址: {{URL}}
```

YAML 可能会把它当成字典结构去解析，导致报错或得到错误的数据。

加上单引号：

```yaml
请求地址: '{{URL}}'
```

就是明确告诉 YAML：

```text
这是一个普通字符串，内容就是 {{URL}}
```

所以，**模板变量一定要加引号**。

### 5.2 YAML 读取后是什么样

`login.yaml` 被读成 Python 字典后，大概是这样：

```python
{
    "基础配置": {
        "用例类型": "ApiCase",
        "用例标题": "商城登录用例标题",
        "一级模块": "登录模块",
        "二级模块": "登录功能"
    },
    "用例步骤": [
        {
            "发送登陆接口": {
                "操作类型": "发送请求POST",
                "请求地址": "{{URL}}",
                "URL参数": {
                    "s": "/api/user/login",
                    "application": "app",
                    "application_client_type": "weixin"
                },
                "请求头": {
                    "Content-Type": "application/x-www-form-urlencoded"
                },
                "请求数据": {
                    "accounts": "youyi",
                    "pwd": "123456",
                    "type": "username"
                }
            }
        }
    ]
}
```

此时 `请求地址` 还是：

```text
{{URL}}
```

它只是一个普通字符串，还没有变成真实网址。

## 6. refresh：把占位符替换成真实值

文件位置：

```text
HAT/utils/VarRender.py
```

完整代码：

```python
import json

from jinja2 import Template


def refresh(target, context):
    """把数据中的 {{变量名}} 替换成全局变量里的真实值"""
    if target is None:
        return None

    if isinstance(target, (dict, list)):
        target_str = json.dumps(target, ensure_ascii=False)
    else:
        target_str = str(target)

    return Template(target_str).render(context)
```

### 6.1 先理解 Jinja2

Jinja2 是一个模板库，它的工作方式是：

```text
模板字符串 + 数据字典 -> 替换后的字符串
```

例子：

```python
from jinja2 import Template

template = "我的名字是 {{name}}"
result = Template(template).render({"name": "youyi"})

print(result)
```

输出：

```text
我的名字是 youyi
```

`{{name}}` 会去 `{"name": "youyi"}` 里面找 `name`，找到后替换成 `youyi`。

本课里的模板是：

```text
{{URL}}
```

数据字典是：

```python
{"URL": "http://shop-xo.hctestedu.com"}
```

替换后得到：

```text
http://shop-xo.hctestedu.com
```

### 6.2 为什么要先 json.dumps

`step_value` 是字典：

```python
{
    "操作类型": "发送请求POST",
    "请求地址": "{{URL}}",
    "请求数据": {
        "accounts": "youyi",
        "pwd": "123456"
    }
}
```

Jinja2 的 `Template` 需要字符串，不能直接处理字典。所以先用：

```python
json.dumps(target, ensure_ascii=False)
```

把字典转成 JSON 字符串：

```text
{"操作类型": "发送请求POST", "请求地址": "{{URL}}", "请求数据": {"accounts": "youyi", "pwd": "123456"}}
```

`ensure_ascii=False` 的作用是：保留中文，不要变成 `\uXXXX` 形式。

然后 Jinja2 在这个字符串里找 `{{URL}}`，替换成真实地址，得到：

```text
{"操作类型": "发送请求POST", "请求地址": "http://shop-xo.hctestedu.com", "请求数据": {"accounts": "youyi", "pwd": "123456"}}
```

### 6.3 为什么后面还要 json.loads

`refresh` 返回的是字符串，不是字典。

但后面的代码需要字典：

```python
key_func(**step_value)
```

`**step_value` 要求 `step_value` 是字典。

所以要把字符串再转回字典：

```python
step_value = json.loads(rendered)
```

完整转换过程：

```text
字典
  -> json.dumps
JSON 字符串
  -> Jinja2 渲染
替换后的 JSON 字符串
  -> json.loads
替换后的字典
```

这就是本课最关键的一段数据处理。

## 7. TestRunner 完整执行流程

文件位置：

```text
HAT/core/TestRunner.py
```

完整代码：

```python
import json

import allure
import pytest
import requests

from HAT.keywords.api_client import Keywords
from HAT.core.globalContext import g_context
from HAT.parse.YamlCaseParser import load_context_from_yaml, readYaml
from HAT.utils.VarRender import refresh


load_context_from_yaml('examples/api-cases-yaml')
data = readYaml('examples/api-cases-yaml/login.yaml')


class TestRunner:
    @pytest.mark.parametrize('caseinfo', data)
    def test_case_exceute(self, caseinfo):
        keywords = Keywords(requests)
        base_info = caseinfo.get('基础配置', {})

        allure.dynamic.parameter('caseinfo', '')
        allure.dynamic.feature(base_info.get('一级模块', '默认模块'))
        allure.dynamic.story(base_info.get('二级模块', '默认模块'))
        allure.dynamic.title(base_info.get('用例标题', '默认用例标题'))

        steps = caseinfo.get('用例步骤', [])
        assert steps, '用例缺少用例步骤'

        for step in steps:
            step_name, step_value = next(iter(step.items()))
            print('没有渲染之前的用例数据', step_value)

            context = g_context().show_dict()
            rendered = refresh(step_value, context)
            step_value = json.loads(rendered)
            print('渲染之后的用例数据', step_value)

            key = step_value['操作类型']
            key_func = keywords.__getattribute__(key)
            response = key_func(**step_value)
            print('发送结果', response.status_code, response.json())
```

### 7.1 第一步：加载环境变量

```python
load_context_from_yaml('examples/api-cases-yaml')
```

读取：

```text
examples/api-cases-yaml/context.yaml
```

把：

```python
{"URL": "http://shop-xo.hctestedu.com"}
```

放进 `g_context`。

### 7.2 第二步：读取用例

```python
data = readYaml('examples/api-cases-yaml/login.yaml')
```

读取 `login.yaml`，得到一条用例数据。

### 7.3 第三步：Pytest 参数化

```python
@pytest.mark.parametrize('caseinfo', data)
def test_case_exceute(self, caseinfo):
```

`data` 是列表，里面有一条用例。Pytest 会把它传给 `caseinfo`。

如果 `data` 里有 3 条用例，这里就会自动生成 3 次测试执行。

### 7.4 第四步：准备 Allure 报告信息

```python
base_info = caseinfo.get('基础配置', {})

allure.dynamic.parameter('caseinfo', '')
allure.dynamic.feature(base_info.get('一级模块', '默认模块'))
allure.dynamic.story(base_info.get('二级模块', '默认模块'))
allure.dynamic.title(base_info.get('用例标题', '默认用例标题'))
```

这些代码只影响 Allure 报告显示，不影响接口请求。

### 7.5 第五步：取出用例步骤

```python
steps = caseinfo.get('用例步骤', [])
assert steps, '用例缺少用例步骤'
```

`steps` 是步骤列表。如果为空，直接断言失败，提示用例缺少步骤。

### 7.6 第六步：循环执行每个步骤

```python
for step in steps:
    step_name, step_value = next(iter(step.items()))
```

`step` 长这样：

```python
{
    "发送登陆接口": {
        "操作类型": "发送请求POST",
        "请求地址": "{{URL}}",
        ...
    }
}
```

`next(iter(step.items()))` 取出第一个键值对：

- `step_name` = `发送登陆接口`
- `step_value` = `{"操作类型": "发送请求POST", "请求地址": "{{URL}}", ...}`

### 7.7 第七步：渲染前打印

```python
print('没有渲染之前的用例数据', step_value)
```

此时输出类似：

```text
没有渲染之前的用例数据 {'操作类型': '发送请求POST', '请求地址': '{{URL}}', ...}
```

可以看到 `请求地址` 还是 `{{URL}}`。

### 7.8 第八步：取出全局变量

```python
context = g_context().show_dict()
```

此时 `context` 是：

```python
{"URL": "http://shop-xo.hctestedu.com"}
```

### 7.9 第九步：渲染

```python
rendered = refresh(step_value, context)
```

把 `{{URL}}` 替换成真实地址，得到字符串：

```text
{"操作类型": "发送请求POST", "请求地址": "http://shop-xo.hctestedu.com", ...}
```

### 7.10 第十步：字符串转回字典

```python
step_value = json.loads(rendered)
```

得到：

```python
{
    "操作类型": "发送请求POST",
    "请求地址": "http://shop-xo.hctestedu.com",
    ...
}
```

然后打印：

```python
print('渲染之后的用例数据', step_value)
```

输出类似：

```text
渲染之后的用例数据 {'操作类型': '发送请求POST', '请求地址': 'http://shop-xo.hctestedu.com', ...}
```

### 7.11 第十一步：动态找到关键字方法

```python
key = step_value['操作类型']
key_func = keywords.__getattribute__(key)
```

`操作类型` 是：

```text
发送请求POST
```

于是去 `Keywords` 类里找同名方法：

```python
def 发送请求POST(self, **kwargs):
    ...
```

`key_func` 就是找到的方法。

### 7.12 第十二步：调用方法发请求

```python
response = key_func(**step_value)
```

`**step_value` 会把字典展开成一个个命名参数：

```python
发送请求POST(
    操作类型="发送请求POST",
    请求地址="http://shop-xo.hctestedu.com",
    URL参数={...},
    请求头={...},
    请求数据={...}
)
```

方法内部再调用：

```python
self.request.request("post", **request_data)
```

真正把请求发出去。

### 7.13 第十三步：打印结果

```python
print('发送结果', response.status_code, response.json())
```

输出类似：

```text
发送结果 200 {'code': 10000, 'msg': '登录成功', ...}
```

这一节还没有做断言，所以“打印出来”只是观察结果，并不代表用例一定会因为业务失败而失败。

## 8. 这一节到底怎么实现“环境动态切换”

重点不是 `context.yaml` 这个名字，而是这个思路：

```text
把环境中会变化的数据，集中放到一个地方
```

比如开发环境：

```yaml
URL: http://dev.example.com
```

测试环境：

```yaml
URL: http://test.example.com
```

正式环境：

```yaml
URL: http://api.example.com
```

不管 URL 怎么变，`login.yaml` 永远是：

```yaml
请求地址: '{{URL}}'
```

你只需要换 `context.yaml` 里的内容，或者以后准备多份 context 文件：

```text
context-dev.yaml
context-test.yaml
context-prod.yaml
```

执行前加载哪一份，用例就跑到哪个环境。

这就是“测试环境动态切换机制”的含义。

## 9. 怎么运行这一节

## 10. 常见报错和排查方法

### 10.1 `FileNotFoundError: ...context.yaml`

原因通常是：

- 当前运行目录不对。
- `examples/api-cases-yaml/context.yaml` 不存在。

排查：

```powershell
Get-ChildItem examples\api-cases-yaml
```

确认里面有 `context.yaml`。

### 10.2 请求地址变成空字符串

如果 `context.yaml` 里没有 `URL`，Jinja2 默认会把 `{{URL}}` 渲染成空字符串：

```text
请求地址: ''
```

然后 requests 可能报：

```text
MissingSchema: Invalid URL ''
```

排查：

- 检查 `context.yaml` 里是不是写的 `URL`。
- 检查大小写，`URL` 和 `url` 不是同一个变量名。
- 看控制台打印的“全局变量”里有没有 `URL`。

### 10.3 `json.decoder.JSONDecodeError`

说明 `refresh` 渲染后的字符串不是合法 JSON。

常见原因：

- YAML 里的引号写错。
- 某个值里有双引号没有转义。
- 缩进错误，导致 YAML 读出来的结构不对。

排查：

先看：

```python
print('渲染之后的用例数据', step_value)
```

如果这里输出的字符串看起来不完整或格式不对，就要回去检查 YAML。

### 10.4 `AttributeError` 或“没有找到关键字方法”

检查 YAML 里的：

```yaml
操作类型: 发送请求POST
```

是否和 `Keywords` 类里的方法名完全一致。

### 10.5 `KeyError: '操作类型'`

说明某个步骤里没有写 `操作类型`。

检查 YAML：

```yaml
操作类型: 发送请求POST
```

### 10.6 `TypeError: ... argument after ** must be a mapping`

说明 `step_value` 不是字典。

常见原因是漏了：

```python
step_value = json.loads(rendered)
```

或者 YAML 读出来的结构不是字典。

## 11. 本节重点记忆

| 名称 | 作用 |
|---|---|
| `context.yaml` | 存放会变化的环境数据，比如 URL、账号、密码、token |
| `g_context` | 内存里的全局变量容器 |
| `_dic` | 类变量，所有 `g_context()` 实例共享同一份数据 |
| `set_dict` | 设置一个全局变量 |
| `set_by_dict` | 批量设置全局变量 |
| `get_dict` | 读取一个全局变量 |
| `show_dict` | 读取全部全局变量 |
| `{{变量名}}` | YAML 里的占位符 |
| `refresh` | 用 Jinja2 把占位符替换成真实值 |
| `json.dumps` | 把字典转成字符串 |
| `json.loads` | 把字符串转回字典 |
| `TestRunner` | 加载环境 -> 读取用例 -> 渲染步骤 -> 动态调用关键字 -> 发请求 |

一句话总结：

> 把会变化的环境数据从用例里抽出来，执行前再填回去。用例只写 `{{URL}}`，环境切换只改 `context.yaml`。

## 12. 新手练习

### 练习 1：增加一个变量

在 `context.yaml` 里增加：

```yaml
URL: http://shop-xo.hctestedu.com
NAME: youyi
```

把 `login.yaml` 里的账号改成：

```yaml
请求数据:
  accounts: '{{NAME}}'
  pwd: "123456"
  type: username
```

运行后观察“渲染之后的用例数据”，确认 `accounts` 变成了 `youyi`。

### 练习 2：故意改错变量名

把 `context.yaml` 里的：

```yaml
URL: http://shop-xo.hctestedu.com
```

改成：

```yaml
url: http://shop-xo.hctestedu.com
```

但 YAML 用例里仍然写：

```yaml
请求地址: '{{URL}}'
```

观察会发生什么，理解大小写和变量名必须完全一致。

### 练习 3：打印全局变量

在 `TestRunner.py` 里加：

```python
print("当前全局变量：", g_context().show_dict())
```

分别在加载 `context.yaml` 之后、渲染步骤之前打印，观察全局变量的变化。

### 练习 4：理解为什么需要 json.loads

在渲染后加一行：

```python
print(type(rendered))
print(type(step_value))
```

你会看到：

```text
rendered 是 <class 'str'>
step_value 是 <class 'dict'>
```

这样就能理解：Jinja2 处理的是字符串，最后还要用 `json.loads` 变回字典。
